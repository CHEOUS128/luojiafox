## 一、接线（最高优先级）

### □ 1.1 VT03 的 RX 接在 STM32 的 PG14

**这是最容易错、也最容易导致"完全收不到"的一项。**

| 要求 | 确认方法 | 你的答案 |
|---|---|---|
| STM32 **PG14**（USART6_TX） | 找到 STM32 板上的 PG14 焊盘/排针 | 接了吗？ |
| 接到 VT03 的 **RX**（不是 TX） | 看 VT03 模块上标着 RX/RXD/R 的脚 | 接对了吗？ |

**必须用万用表验证，不能凭记忆**：

```
断电 → 万用表蜂鸣档
表笔 A：STM32 的 PG14 焊盘
表笔 B：VT03 的 RX 引脚
听到蜂鸣 = 线通 ✅
```

然后再验一次**接错的情况**：

```
表笔 A：STM32 的 PG14
表笔 B：VT03 的 TX 引脚
应该【不响】。如果响了，说明接反了 ❌
```

> ⚠️ **PG14 是发送端，必须接对方的接收端。** 两边都接 TX 就永远收不到。
> 这是 RoboMaster 队伍最常犯的接线错误。

### □ 1.2 GND 必须共地

| 要求 | 确认方法 |
|---|---|
| STM32 GND ↔ VT03 GND | 万用表通断，必须蜂鸣 |

**没有共地线的症状**：完全收不到，或者画面偶尔闪一下又断。

### □ 1.3 VT03 供电是否正常

| 检查 | 标准 |
|---|---|
| VT03 电源指示灯 | 亮 |
| 电压 | 符合 VT03 规格（常见 5V 或 12V） |
| 电流 | 用万用表串测，不应异常偏小 |

### □ 1.4 线材质量（921600 对线材有要求）

| 项 | 要求 |
|---|---|
| 线长 | **≤ 30cm**（超过 50cm 风险很高） |
| 走线 | 信号线与 GND 成对走，**不要和电机线/电源线捆一起** |
| 类型 | 建议双绞线；普通杜邦线短距离可以 |

> 921600 波特率下一个 bit 只有 1.08μs。长线 + 无屏蔽 + 靠近电机线，
> 误码率会高到几乎收不到数据。

### □ 2.2 USART6 引脚复用

`HAL_UART_MspInit()` 中 `USART6` 分支：

| 项目 | 必须是 |
|---|---|
| 使能时钟 | `__HAL_RCC_USART6_CLK_ENABLE()` 和 `__HAL_RCC_GPIOG_CLK_ENABLE()` |
| 引脚 | `GPIO_PIN_14 \| GPIO_PIN_9` |
| 模式 | `GPIO_MODE_AF_PP` |
| 复用号 | **`GPIO_AF8_USART6`** |
| 速度 | `GPIO_SPEED_FREQ_VERY_HIGH` |

### □ 2.3 ★ 关键：HAL_UART_Transmit 是否使用了 TX DMA

**这是本次审查新发现的隐患。**

`MX_USART6_UART_Init()` 里注册了 **TX DMA**（`hdma_usart6_tx`，DMA2_Stream6）。

而 `VideoForward_Task()` 用的是：

```c
HAL_UART_Transmit(VIDEO_VT03_HANDLE, (uint8_t *)frame, 309, 20);
```

**这是"阻塞式"发送，不是 DMA 发送。**

**问题**：如果 `huart6.hdmatx` 已关联，某些 HAL 版本会在 `HAL_UART_Transmit`
内部尝试使用 DMA，或者状态机忙标志冲突，导致发送卡住或返回 `HAL_BUSY`。

**请确认**：

| 检查 | 说明 |
|---|---|
| `VideoForward_GetForwarded()` 是否在增长 | 增长说明 `HAL_UART_Transmit` 返回了 `HAL_OK` |
| 如果 `forwarded` 不增长 | 说明返回了 `HAL_BUSY`/`HAL_TIMEOUT`，**需要改成 DMA 发送或断开 TX DMA 关联** |

**如果确认是这个问题**，两种改法（任选其一）：

```c
// 改法 A：断开 DMA 关联，用纯阻塞发送
huart6.hdmatx = NULL;

// 改法 B：改用 HAL_UART_Transmit_DMA（需要处理回调）
HAL_UART_Transmit_DMA(VIDEO_VT03_HANDLE, frame, 309);
```

> **请先读计数器判断，不要盲目改。** 如果 `forwarded` 在涨，说明这一项不是问题。

## 三、运行时验证（必须提供数据）

### □ 3.1 读三个计数器（最重要）

让车跑 **30 秒**，然后在调试器里读：

| 计数器 | 你的读数 | 含义 |
|---|---|---|
| `VideoForward_GetForwarded()` | ______ | 成功转发给 VT03 的帧数 |
| `VideoForward_GetCrcError()` | ______ | 收到但 CRC 错误的帧数 |
| `VideoForward_GetOverflow()` | ______ | 队列溢出丢弃数 |

**30 秒的预期值**：`forwarded ≈ 300`（10fps × 30 秒）

#### 结果判读表

| 组合 | 结论 | 下一步 |
|---|---|---|
| `forwarded` 增长到 300 左右 | STM32 收到并调用了发送 | **问题在 PG14 之后的物理链路**，回到第一节 |
| `forwarded = 0`，`crcError = 0` | 一个 0xA5 帧都没收到 | STM32 没从 USB 收到视频 → 查 `usbd_cdc_if.c` |
| `forwarded = 0`，`crcError` 在涨 | 收到字节流但校验失败 | 帧损坏 → 查 USB 接收是否丢数据 |
| `overflow` 在涨 | 转发太慢 | VT03 没接收 / HAL 返回 BUSY |

### □ 3.2 ★ 用示波器量 PG14（唯一能 100% 确认的方法）

**如果有示波器或逻辑分析仪，请务必做这一步。**

| 步骤 | 操作 |
|---|---|
| 1 | 机器人上电，Jetson 跑自瞄程序（`video_send_enable: true`） |
| 2 | 探头接 **PG14**，地夹接 **GND** |
| 3 | 时基设 10ms/格，电压 1V/格 |

**正常波形特征**：

| 特征 | 预期值 |
|---|---|
| 空闲电平 | 高（3.3V） |
| 数据突发间隔 | 约 25ms（40Hz 节拍） |
| 单次突发时长 | 约 3.35ms（309 字节 ÷ 921600） |
| 突发期间 | 密集方波，bit 宽约 1.08μs |

**判读**：

| 波形 | 结论 |
|---|---|
| 有数据突发 | ✅ STM32 在正确输出，问题在接线或 VT03 |
| 完全没有数据 | ❌ STM32 没在发 → 回到 3.1 读计数器 |
| 有数据但波形畸变/幅度不足 | ❌ 引脚配置或硬件问题 |

## 五、审查中发现的一个潜在隐患（请评估）

### 5.1 VideoForward_Task 可能阻塞 200Hz 任务

当前代码：

```c
void Self_aim_task(void const *pvParameters)
{
    VideoForward_Init();
    while(1)
    {
        USART1_SEND();
        VideoForward_Task();    // 可能阻塞
        osDelay(5);
    }
}
```

而 `VideoForward_Task()`：

```c
while (s_tail != s_head)                    // 队列里有多少就发多少
{
    HAL_UART_Transmit(..., 309, 20);        // 每帧最多阻塞 20ms
    ...
}
```

**风险分析**：

| 场景 | 后果 |
|---|---|
| VT03 正常接收 | `HAL_UART_Transmit` 约 3.4ms 返回，队列正常清空 |
| VT03 没接/没上电 | 每帧阻塞到 20ms 超时，队列迅速积压到 8 帧，**这个任务会卡住 160ms** |

**这不会导致本次"收不到画面"**，因为超时只影响速度。
但如果不接 VT03 测试，会看到自瞄 FPS 下降。

**建议（可选）**：把 `HAL_UART_Transmit` 超时从 20ms 降到 5ms，
或者在 `while` 循环里加一个单次最多发 2 帧的限制。

> **这不是当前问题的原因，是代码健壮性建议。** 可以等第二视角通了再改。

## 附：为什么一定是 PG14

协议规定图传链路要求 921600 波特率。工程里的三个串口：

| 串口 | 波特率 | 每秒可传 | 视频需求 12000 B/s |
|---|---|---|---|
| USART1（裁判系统） | 9600 | 960 B/s | ❌ 差 12 倍 |
| USART3（DBUS 遥控） | 100000 | 10000 B/s | ❌ 不够 |
| **USART6** | **921600** | **92000 B/s** | ✅ 充裕 |

视频只能走 USART6，而 USART6 的 TX 就是 **PG14**。这一点没有其他可能。
