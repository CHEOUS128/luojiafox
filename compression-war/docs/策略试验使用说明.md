先看本轮结果：[2026-11-09策略验收](验收/策略探索-2026-11-09.md)。原始双包基线保持不变；所有候选独立运行，接收画面来自真正收到的300 B包。C板旁路，官方无线链路仍是理想模型。

## 先看画面，再选方案

本轮先看“原来的办法”、A和B。A对应`one-320`，兼顾清楚与掉图后的恢复；B对应`one-320-gop20`，更偏重细节。正常播放两者通常都只晚约0.1秒；故意漏掉一包那次，A约0.36秒恢复，B约0.86秒恢复。这不是说每张图都要等这么久。

2026-11-10，CH看完对比后选择B作为本轮上车试验版；原方案和A保留作对照。点“播放”看移动时跟不跟手，切到“停下来看清楚”对比同一时刻。只需要看车、障碍、线条和红蓝颜色好不好认；其他试验没有删，展开“其他办法”可以继续比较。详细参数默认收起。

现有相机片段主要拍地面，能比较线条，但不足以决定远处装甲板能否看清。上车时再看真实目标。本轮选择已经确定为B，下一步以上车验证为主，后续再优化。

## 队员最短运行路径

先按[主README](../README.md)编译、准备FFmpeg。对比导出另外需要Python 3、`numpy`和`Pillow`（`python -m pip install numpy pillow`）。运行脚本优先使用本机已有的Codex Python，找不到才使用PATH中的Python，也可用`-Python`指定。

在`compression-war`目录执行：

```powershell
# 有原片时默认使用 素材/car_raw.bgr；也可以提供普通视频。
powershell -NoProfile -ExecutionPolicy Bypass -File '.\scripts\运行-策略对比.ps1' -InputPath 'D:\视频\比赛录像.mp4'
# 再次打开最近的结果，无需重跑。
& '.\scripts\启动-策略对比.bat'
```

每档先开真实仿真窗口、按正常速度运行，结束后独立核对接收包并导出图片；全部运行结束后才计算质量统计。测量时保持桌面解锁、窗口可见，不最小化，不使用桌面自动化操作窗口；不要同时运行其他编码测试。本轮观察到窗口自动化调用期间的显示掉帧，原始失败已保留。锁屏时仍可写包和提交绘制，不能据此声称操作手看到了相同的刷新率。结果在新的`runs/strategies/<时间>/`，已有目录默认拒绝覆盖。

没有相机素材可以运行`生成演示视频.ps1`，或者`python tools/make_strategy_stress.py --help`生成明确标记的合成运动素材。合成数据与相机原片分开报告。

## 两种对比各看什么

- **操作体验**：共享源时间轴，以每档真实提交显示时刻更新右栏。未到包保持空白；冻结保持上一张、画面年龄继续增加。看转向时的延迟、卡顿和新图fps。
- **同帧画质**：按同一源帧编号对齐；没有解出该源帧就留空。支持原片、基线及任意多个候选、共同位置放大和原生像素1:1。看小字、轮廓、运动块效应、颜色。
- 原片只用于左栏和运行后的评价，不进入接收端。右栏PNG是独立收包重放输出，逐张对照实时后处理像素SHA256。PNG文件大小不是无线传输大小。
- 分辨率、GOP、AQ、颜色处理、后处理及实际VCL分片数都公开；参数`slices`受x264线程配置影响，不能把声明值当实际分片数。
- 页面上的本段PASS只说明该短片窗口，**入围实时验收看60秒重复测试，包括失败轮次**。

## 自选策略，不限制数量

`profiles/*.ini`是统一配置入口。复制一份、改`name/label/family`及所需参数即可；未知键、重复键、非法尺寸、超25fps都会拒绝。命令行、窗口菜单“选择策略配置（停止时）”、报告读取同一配置。

```powershell
# 实时看一档
.\cw_live.exe --input '.\素材\car_raw.bgr' --profile '.\profiles\one-320-aq0.ini' --autostart
# 自选任意数量；每档依次运行，并生成对比播放器
python .\tools\run_strategies.py --out .\runs\strategies\my-test --profiles baseline one-160 one-320-aq0 one-320-gop20 gray sharp --duration 15
# 真实窗口长测；质量统计不与实时链路抢资源
python .\tools\run_strategies.py --out .\runs\strategies\my-60s --profiles baseline one-320-aq0 --duration 60 --repeat 3 --no-export --no-compare
python .\tools\summarize_strategy_runs.py .\runs\strategies\my-60s
```

配置项：

| 部位 | 配置 |
|---|---|
| 元数据 | `name`、`label`、`family` |
| 全视野前处理 | `width/height`、`color=color/gray`、`denoise`（双边滤波强度）、`temporal`（因果时域门限）、`chroma_block`（粗色彩块） |
| 编码 | `fps`、`preset`、`gop`、`threads`、`slices`、`aq`、`aq_strength`、`bitrate`（0=约74548bps推导值） |
| 接收后处理 | `upscale`（双三次倍数）、`sharpen`（受限反锐化） |
| 计量 | 配置入口默认`offline_metrics=1`，质量统计放在运行结束后 |

灰度候选先把BGR变成中性灰，再编码YUV420P；**不等同车端历史GRAY8/H.264 4:0:0档**。粗颜色通过实际H.264图像传输，未使用旁路信息。本轮没有启用推测上色、生成模型或插帧；没有把这些未实装路线写成收益。

未来非H.264表示必须同时扩展实际编码、接收及独立重放。目前编码入口有统一配置，但接收器只接受H.264；仅改展示图不算新编码方案。

## 可复核证据和回归

```powershell
.\cw_wire_verify.exe --fast --export '.\runs\strategies\my-test\one-320-aq0'
.\cw_wire_verify.exe --rx-only --fast '.\runs\strategies\my-test\one-320-aq0'
python .\tools\verify_strategies.py --out .\runs\strategies\my-fault-tests
powershell -NoProfile -ExecutionPolicy Bypass -File '.\scripts\验证-双包实时仿真.ps1' -Full
```

`--fast`仅加速**运行结束后的独立重放**，不产生实时延迟成绩。验证器仍检查原始到包时间的20ms间隔、滚动一秒50包、CRC及592 B/2包上限。RX-only只需要`rx-300.bin`、`rx-times.csv`、`decoded.csv`、`processed.csv`、`receiver.ini`；后两个必须成对出现，接收配置禁止原片路径等非接收键。

| 文件 | 用途 |
|---|---|
| `experiment.json`、`strategy.ini`、`encoder-args.txt` | 素材、程序、配置、源码校验值与实际参数 |
| `tx-0310.bin / tx-times.csv` | 实际309 B外层帧、发送/丢弃状态、逐包时间 |
| `rx-300.bin / rx-times.csv` | 真正到接收队列的300 B包与时间 |
| `decoded.csv / processed.csv` | 解码前后处理输出摘要，独立重放逐帧比对 |
| `source-map.csv / decoded-association.csv` | 只供观测和离线对比的源帧关联，不帮助接收还原 |
| `display.csv / display-seconds.csv` | 真实窗口提交时刻、每个稳态完整秒的新源帧数 |
| `per_frame.csv / events.csv / summary.txt` | 阶段耗时、覆盖/超限/积压/丢包及汇总 |
| `source-quality.csv / comparison.json` | 运行后相对未经候选处理原片的统一尺度评价 |

源码接口在`src/strategy.h/.cpp`：`preprocess_strategy`运行于实际编码线程，`reconstruct_pixels`运行于实际接收线程。后者只接收已解码像素和声明参数；`ProcessingState`由每个会话独立持有，重新播放不继承上一会话。

实时约束没有策略配置开关：每帧包括IDR≤592 B、最多2包、300 B数据段、50包/s、逐包≥20ms；超限整帧丢弃。正常20fps档遇到冻结或低于15fps如实FAIL，不自动换尺寸。
