# 小电脑上车步骤

B 在 Windows 仿真里叫 `one-320-gop20`，在 Jetson 上叫 `quality`。先准备好独立试验目录，现场再切档。Jetson 编译和整车出图都要到车上确认。

## 1. 用 ToDesk 找到小电脑

1. 在 Windows 打开 ToDesk，连车上的小电脑。在小电脑的应用列表搜“终端”并打开。看到 Linux 提示符后，粘贴下面这段。

   ```bash
   whoami
   hostname
   ip -br -4 addr
   systemctl show autoaim-20261025 -p ActiveState -p WorkingDirectory -p ExecStart
   mkdir -p "$HOME/cw_transfer"
   ```

2. 这台车原记录的用户名是 `nvidia4`，工作目录是 `/home/nvidia4/my_lf_INF_20261025`。如果看到别的用户名、服务或路径，把这几行输出发回来，按车上的实际位置调整命令。
3. 在 ToDesk 的文件传输里选 Windows 仓库 `compression-war/runs/delivery/` 中的 **`RM26_cw_trial_20261109_r2.zip`** 和 **`RM26_cw_trial_20261109_r2.sha256`**，放进 Jetson 的 **`/home/nvidia4/cw_transfer/`**。

本机这份 ZIP 的 SHA256 是 `e6dcb827598847accc45389ac1865de5a9b9cd8f325c08723f4c5c7b1c33b390`。下文会自动核对。新拉下仓库的人需要自己生成 ZIP 和校验文件，在仓库根目录用可运行的 Python 3 执行：

```powershell
python '.\compression-war\tools\package_vehicle_trial.py' --out '.\compression-war\runs\delivery\RM26_cw_trial_20261109_r2.zip'
```

## 2. 可选，用网线让 Codex 从 Windows 看终端

只通过 ToDesk 也能做完第 1、3、4 步。需要我后续读日志或帮你查编译时，用 **SSH**，也就是从 Windows 打开小电脑的文字终端。

1. 把 Jetson 网线插到你电脑所在路由器的 LAN 口。Windows 可以连同一个路由器的 WiFi。保留客户端和官方端之间的比赛网线接法。Jetson 终端执行 `ip -br -4 addr`，记下网线对应那行的地址，例如 `192.168.1.53/24` 只填 `192.168.1.53`。执行 `systemctl status ssh --no-pager` 看 SSH 是否已开。
2. 若 SSH 已装但显示 `inactive`，在 Jetson 终端执行 `sudo systemctl start ssh`。若提示找不到 `ssh.service`，用 `sudo apt install openssh-server` 安装，再执行启动命令。首次连接前可在 Jetson 用 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` 看指纹，对照 Windows 第一次提示的 ED25519 指纹。 [Ubuntu OpenSSH 文档](https://ubuntu.com/server/docs/how-to/security/openssh-server/)
3. 在 **Windows PowerShell** 粘贴下方命令，按提示填上一步查到的地址和用户名。`TcpTestSucceeded` 为 `True` 就说明 Windows 能找到 Jetson 的 SSH 端口。Jetson 密码只在本机提示时输入，输入时屏幕不会显示字符。登录后看到 Jetson 的提示符就成功了。输 `exit` 回到 Windows。 [Microsoft 端口检查说明](https://learn.microsoft.com/en-us/powershell/module/nettcpip/test-netconnection)

   ```powershell
   $jetsonIp = Read-Host '输入 Jetson IP'
   $jetsonUser = Read-Host '输入 Jetson 用户名，例如 nvidia4'
   $jetson = "$jetsonUser@$jetsonIp"
   Test-NetConnection -ComputerName $jetsonIp -Port 22
   ssh $jetson
   ```

4. 想让 Codex 在你电脑上自动登录，可以为这台车单独建一把 SSH 钥匙。继续用刚才的 PowerShell，先从 Jetson 输入 `exit` 回来，再复制下方命令。首次创建时会问两次钥匙口令，要让命令自动登录，可以两次直接按回车。随后输入一次 Jetson 登录密码，把公钥放上去。最后一行能直接显示车上电脑名，就把 IP、用户名和成功结果告诉我。私钥和登录密码都留在你本机。

   ```powershell
   $key = Join-Path $env:USERPROFILE '.ssh\rm26_jetson'
   New-Item -ItemType Directory -Force -Path (Split-Path $key) | Out-Null
   if (-not (Test-Path -LiteralPath "$key.pub")) { ssh-keygen -t ed25519 -C rm26-codex -f $key }
   if (-not (Test-Path -LiteralPath "$key.pub")) { throw '公钥还没生成' }
   $pub = (Get-Content -LiteralPath "$key.pub" -Raw).Trim()
   ssh $jetson "umask 077; mkdir -p ~/.ssh && printf '\n%s\n' '$pub' >> ~/.ssh/authorized_keys"
   ssh -i $key -o IdentitiesOnly=yes -o BatchMode=yes $jetson hostname
   ```

传车上的源码仍用第 1 步的 ToDesk 文件传输。

## 3. 在 Jetson 编译并检查版本

把下面整段粘到 **Jetson 终端**。如果已有试验目录，命令会停下来。第一次先确认它的来源，有需要可以在文件管理器把旧试验目录改名留档，再重新运行。这段准备工作不启动自瞄。

```bash
(
    set -eo pipefail
    base="$HOME/my_lf_INF_20261025"
    trial="$HOME/my_lf_INF_20261025_cwtrial"
    transfer="$HOME/cw_transfer"
    test "$(systemctl show autoaim-20261025 -p WorkingDirectory --value)" = "$base" || {
        echo '现役服务目录与说明不一致，先核对上一步输出。'; exit 1;
    }
    test ! -e "$trial" || { echo "试验目录已存在：$trial"; exit 1; }
    cd "$transfer"
    sha256sum -c RM26_cw_trial_20261109_r2.sha256
    python3 - "$base" "$trial" <<'PY'
import shutil
import sys
shutil.copytree(sys.argv[1], sys.argv[2], symlinks=True,
                ignore=shutil.ignore_patterns('build', 'build_cw', 'records', 'logs', '.git'))
PY
    cd "$trial"
    unzip -o "$transfer/RM26_cw_trial_20261109_r2.zip"
    sha256sum -c SHA256SUMS
    cmake -G 'Unix Makefiles' -S . -B build_cw
    cd build_cw
    make standard_mpc video_sender_test -j2
    ./standard_mpc --help | grep 'cw-trial-20261109-r2'
    ./video_sender_test --help | grep 'cw-trial-20261109-r2'
    stat -c '%y %s %n' standard_mpc video_sender_test
)
```

ZIP 和 8 个源码都显示 `OK`，且两个 `--help` 都打印 `cw-trial-20261109-r2`，再继续。编译卡住或报错时，发终端原始报错。构建完成后，先跑 15 秒本地合成画面，检查 B 能否编码。这条测试只在本机生成文件。

```bash
cd "$HOME/my_lf_INF_20261025_cwtrial" && ./build_cw/video_sender_test /tmp/cw-quality-check --cw-profile quality --seconds 15
```

结果看终端输出和 `/tmp/cw-quality-check/cw-packet-times.csv`，现场再看 `[CW timing]` 和客户端出图。USB 写入计时与云台 USART6 线上时间分别记录。

## 4. 现场切档，测完切回来

先让电控隔离发射机构、确认云台可以安全转动。现役配置可能启用自动发射，这两档试验程序也会下发控制。现场按首页顺序，先用原服务试云台修复。随后在 **Jetson 终端**停原服务，运行双包基线。原服务用管理员权限访问相机和串口，试验也用 `sudo`：

```bash
cd "$HOME/my_lf_INF_20261025_cwtrial" && \
grep -En '^video_send_enable:[[:space:]]*true([[:space:]]|$)' configs/standard3.yaml && \
sudo systemctl stop autoaim-20261025 && \
sudo ./build_cw/standard_mpc configs/standard3.yaml --cw-profile=baseline
```

图传配置应显示 `video_send_enable: true`。下面这段在 **第二个 Jetson 终端**执行，先结束基线，再启动 B。看到“还在退出”时等前台进程结束，重新运行这一段。

```bash
(
    set -e
    trial_pattern='^\./build_cw/standard_mpc configs/standard3\.yaml --cw-profile='
    if pgrep -f "$trial_pattern" >/dev/null; then
        sudo pkill -INT -f "$trial_pattern"
        sleep 2
    fi
    if pgrep -f "$trial_pattern" >/dev/null; then
        echo '试验程序还在退出，先等它结束。'; exit 1
    fi
    if systemctl is-active --quiet autoaim-20261025; then
        echo '原服务还在运行，先停原服务。'; exit 1
    fi
    cd "$HOME/my_lf_INF_20261025_cwtrial"
    sudo ./build_cw/standard_mpc configs/standard3.yaml --cw-profile=quality
)
```

测完在另一个 Jetson 终端跑下面一段，恢复平时开机跑的服务：

```bash
(
    set -e
    trial_pattern='^\./build_cw/standard_mpc configs/standard3\.yaml --cw-profile='
    if pgrep -f "$trial_pattern" >/dev/null; then
        sudo pkill -INT -f "$trial_pattern"
        sleep 2
    fi
    if pgrep -f "$trial_pattern" >/dev/null; then
        echo '试验程序还在退出，先等它结束。'; exit 1
    fi
    sudo systemctl start autoaim-20261025
    systemctl status autoaim-20261025 --no-pager
)
```

看到 `active (running)` 后用客户端确认原配置出图。原服务目录保存着本车的现役版本和配置。
