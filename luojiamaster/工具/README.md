# 客户端工具和现场接线

这里是当前2026现役工程唯一的现场组网说明。普通使用看 [客户端 README](../README.md)。2027 RMUL接入方式和角色变化另行核对，本轮不改变现有A/B队友行为。

## 两个入口分别做什么

| 入口 | 用途 |
| --- | --- |
| `维护工具.bat` | 查看本机配置、检查真实对端、手工选择A/B/off，以及经确认修改专用队友网卡或添加防火墙规则 |
| `离线测试.bat` | 用小份真实双路录流检查解码、显示和窗口；只进入独立离线测试，不创建正常客户端网络服务 |
| `内部/` | 两个入口调用的实现，平时不用单独打开 |

维护菜单的检查与修改分开：

1. **只看本机：** 网卡、角色ini、EXE校验值和现有规则。
2. **检查对端：** 官方端及当前ini中的队友地址；拒绝把本机IP当作对端，避免“ping自己也算通过”。
3. **选择角色：** 手工写入A、B或off；不替你启动或登录客户端。
4. **设置队友网卡：** 显示网卡编号、MAC和现有地址，明确选择并再次确认。不能覆盖官方链路、上网网卡或其他业务网络。
5. **添加放行规则：** 管理员权限下明确确认，仅添加本程序需要的局域网入站规则。

离线测试读取 `源码/tests/fixtures/双路视频样本.bin`，官方UDP分片和300 B第二视角数据都经过真实解码，再提交显卡显示；不把普通彩色图片代替视频链路。默认样本是可复核的小片段，不是完整实车会话，也不代表相机到屏幕延迟已测完。

**离线回放没有官方登录，也不向车辆发布键鼠。两个回放窗口各自播放，不能据此宣布A/B互联通过。** 原来的正常客户端双开/灌UDP脚本已退出日常入口；需要检验两机互联时，按下方真实网卡和真实画面逐项验收。

## 单车先接通官方端

只用一台车时，先完成官方端与客户端这一对，不必同时搭队友线。

```text
VT13接收端 → 官方端电脑的USB
官方端自带网口192.168.12.1 ──网线── 客户端自带网口192.168.12.2
```

两端掩码均为 `255.255.255.0`，这个专用网口的网关和DNS留空。官方端应已登录赛事引擎并能显示图传；本仓库2026记录验证过 `RoboMasterClient 12.0.0.213`，旧 `12.0.0.30` 没有可用的自定义客户端接入。未来版本按实际接口测试确认。

Windows手工设地址的通用点法只需学一次：

1. 按 `Win+R`，输入 `ncpa.cpl`，回车打开网络连接。
2. 先认网卡。自带RJ45、USB网卡、WLAN、手机共享分别承担不同用途；名字会随插口变化，以设备描述、MAC和实际接线核对。
3. 右键选定网卡 → 属性 → 双击“Internet协议版本4（TCP/IPv4）”。
4. 选择“使用下面的IP地址”，填地址和掩码；专用网口的网关、DNS留空 → 确定。
5. 用 `ipconfig` 核对。不要改到无线网卡、手机共享或另一条业务链路上。

本机PowerShell检查：

```powershell
Test-NetConnection 192.168.12.1 -Port 3333
```

`TcpTestSucceeded : True` 表示该对端端口可达；仍需在官方端确认画面及机器人ID。官方端按 `P` 选择自定义客户端键鼠来源；自定义客户端连接 `192.168.12.1:3333`，选相同队伍和机器人，登录后 `Esc` 进入比赛模式。

**客户端不要按Ctrl。** `P` 属于官方端，本客户端没有P设置面板。

## 四台电脑的当前摆法

本车2026现场复现用四台电脑：PC-A为步兵官方端并运行引擎，PC-B为英雄官方端，PC-C/D为对应自定义客户端。两套机器人主控连同一个2.4G路由器；官方端到客户端和队友互看均走独立网线。

```text
路由器LAN192.168.1.1
  WiFi → PC-A引擎/官方端192.168.1.2、PC-B官方端DHCP、两套机器人主控
  PC-A另接手机USB共享，给引擎提供外网

PC-A RJ45 192.168.12.1 ──线1── PC-C RJ45 192.168.12.2
PC-B RJ45 192.168.12.1 ──线2── PC-D RJ45 192.168.12.2
PC-C USB网卡10.77.0.1 ═══线3═══ PC-D USB网卡10.77.0.2
```

两条12.x线中间没有交换机，物理隔离，所以两个 `.1` 和两个 `.2` 不冲突。队友线必须使用另一块网卡，不能把两条官方线桥接到一起。官方视频来自各自VT13和官方端，经专用12.x网线送到客户端；不要把赛事WiFi和这段视频网线混为一条链路。

准备3根Cat5e及以上网线、2块USB千兆网卡、两套VT13，以及给PC-A外网使用的手机数据线。默认前提是四台电脑各有自带RJ45和WiFi。

| 电脑 | 网卡用途 | 地址 | 网关/DNS |
| --- | --- | --- | --- |
| PC-A | WLAN接赛事路由器 | `192.168.1.2/24` | 空 |
| PC-A | 自带RJ45接PC-C | `192.168.12.1/24` | 空 |
| PC-A | 手机USB共享外网 | 自动获取 | 自动 |
| PC-B | WLAN接赛事路由器 | DHCP获取1.x | 自动 |
| PC-B | 自带RJ45接PC-D | `192.168.12.1/24` | 空 |
| PC-C | 自带RJ45接PC-A | `192.168.12.2/24` | 空 |
| PC-C | USB队友网卡接PC-D | `10.77.0.1/24` | 空 |
| PC-D | 自带RJ45接PC-B | `192.168.12.2/24` | 空 |
| PC-D | USB队友网卡接PC-C | `10.77.0.2/24` | 空 |

C/D的WiFi可不连接；如连接赛事局域网，保持DHCP。路由器没有外网时，连上它不代表能够下载GitHub文件。只在PC-A上要求本方案的默认外网路由由手机共享提供，不能把“其他三台网关也一律清空”当作通用规则。

## 按顺序搭好这套网络

### 1 配置路由器

1. 用设备背面给出的地址登录管理页，小米常见 `192.168.31.1`，其他型号以标签为准。
2. 在“高级设置→局域网/LAN/DHCP”中把LAN改为 `192.168.1.1/24`；开DHCP，地址池例如 `.100–.249`，不要把静态引擎地址 `.2` 放进池内。
3. 配置2.4G WiFi，SSID例如 `RM26`，密码 `12345678`，WPA2-PSK。这是本套2026主控接入的配置；5G可单独命名，主控连2.4G。
4. 保存重启后改用 `192.168.1.1` 登录。管理页中“上网/WAN”不是LAN设置，别改错菜单。
5. 手机接入后应拿到 `192.168.1.x`。本方案由PC-A手机共享提供外网，路由器WAN可空着。

### 2 配PC-A和PC-B

- PC-A：WLAN设 `.1.2`，RJ45设 `.12.1`，两者不填网关；手机开USB共享，其新网卡保持自动获取。浏览器应能上网，`route print` 检查默认外网路由走手机。
- PC-B：WLAN保持DHCP，RJ45设 `.12.1`。不能把PC-B WLAN也设成 `.1.2`。
- 两套VT13分别插自己的官方端，记录设备管理器里的COM号，按官方端配置选择。
- 赛事引擎及官方端防火墙设置按对应2026官方联网手册核对。客户端的放行工具只用于客户端，不能拿它代替官方端的接入检查。

### 3 配PC-C和PC-D

1. **先接官方线**，两台自带RJ45分别设 `.12.2`，各自检查自己那台 `.12.1:3333`。
2. 再插USB队友网卡，C设 `10.77.0.1`，D设 `10.77.0.2`。可手填，或在维护菜单中明确选择网卡后确认。
3. 两台客户端分别添加本程序必要规则：入站TCP47700、UDP3334和需要的ICMP回显。维护工具添加前会确认；不要因此关闭所有无关防护。
4. 双击同一版本EXE，选「进入正式客户端」后选同一赛事。C保留A角色，D点标题 `[默认A]` 切为B，或用维护工具提前手工设置；该操作不负责官方登录。
5. 角色选择后看EXE旁的 `队友视角.ini` 和日志。两台EXE的MD5必须一致。

### 4 开引擎、官方端和客户端

1. PC-A启动 `RoboMasterEngine`，“本地IP配置测试”和“外网连接测试”分别通过，再登录使用。
2. 两台机器人主控按既有流程上电，确认在线。执行器状态由现场电控确认。
3. PC-A/PC-B启动官方选手端，连接引擎 `192.168.1.2`，分别选择对应机器人，确认官方图传正常。
4. 两台官方端按 `P`，键鼠来源选“自定义客户端”。
5. PC-C/D分别登录 `192.168.12.1:3333`，机器人ID各自与对应官方端一致；登录后按 `Esc`。
6. 主画面应是本车，队友小窗应是另一台车。标题“双向已连”只是连接信息，还要确认画面来源及持续更新。

分级验收：先每一对官方端/客户端自己出画，再连两台客户端互看，最后检查赛事数据和工业相机第二视角。哪一级失败就查新加的一段，不同时改多处。

## 常见故障怎么查

| 现象 | 核对顺序 |
| --- | --- |
| 引擎本地IP测试失败 | PC-A是否在赛事局域网的 `.1.2`，掩码是否24位，与主控是不是同一路由器 |
| 引擎外网测试失败 | 手机共享是否正常；PC-A是否错误地给12.x/WLAN加了默认网关；网页能开不代替引擎测试通过 |
| 主控不在线 | 2.4G、WPA2、密码、DHCP网段；别把WiFi连到无关热点 |
| `.12.1:3333`不通 | 官方端程序是否登录并监听；网卡地址是否正确；线是否接到了对应官方端 |
| 客户端主画面黑 | 先看官方端自身画面，再查ID和客户端入站UDP3334 |
| 队友未连接 | 检查真实对端10.77地址、角色、TCP47700；不要测试自己的IP |
| 有连接但没队友新图 | 对方官方源是否有图；发、收、解码计数在哪里先停；接收端是否在等恢复关键帧 |
| 接受端口自动变成47701等 | 47700被占后会向上尝试9个端口；对方仍找47700不会自动知道新端口，先关重复实例或明确配对端口 |
| 图像越来越旧或主画面受影响 | 看CPU/GPU、队列、丢旧帧和新图计数；折叠小窗不会停止解码，可用off关闭队友功能后重启客户端 |
| 工业相机第二视角不出图 | 先用 [Jetson只读检查](../../autoaim/README.md#日常开机与只读检查)，再看 [云台输出证据](../../lower-machine/README.md)；不靠键鼠或运动“保活” |

对端端口检查可以用维护菜单，也可在PowerShell运行：

```powershell
Test-NetConnection 192.168.12.1 -Port 3333
Test-NetConnection 10.77.0.2 -Port 47700
```

上例第二条用于C查D，D查C应换成 `10.77.0.1`。连接测试不是画面验收；`ping`失败也可能只是ICMP没放行，不能只凭它判网线坏。日志位于 `程序/logs/<会话>/robogo.log`，同时保留原始输出和发生时间。

## 角色配置与恢复

大多数时候点击A/B即可。确需自定义地址时，EXE旁 `队友视角.ini` 为UTF-8，一行一项：

```ini
role=A
peer=10.77.0.2:47700
listen=47700
```

优先级是命令行 `--teammate-*`、ini的 `peer=`、`role=`、内置默认A。显式写 `peer=` 后就以该地址为准，不能以为只改角色就必然改掉显式对端。`peer=off` 关闭队友连接和监听。联盟赛仍留一行提示，按 K 可查看原因。删除本机 ini 恢复默认。该文件是每台电脑的配置，不提交到Git。

收场后，需要恢复日常网络的网卡，在IPv4属性改为“自动获得IP地址/DNS”。只撤销本次新增的规则，不随意改其他程序配置。更换USB接口后Windows可能建立新网卡配置，要重新核对MAC、接口编号和IP。

<summary>有线赛事局域网备选与路由器排错</summary>

当前复现主线使用WiFi赛事局域网。若现场条件允许，可把引擎和官方端接路由器LAN，官方端再用另一块网卡接客户端：

| 设备 | 赛事局域网 | 官方专线 | 队友专线 |
| --- | --- | --- | --- |
| PC-A引擎/官方端 | RJ45 `192.168.1.2/24` | USB网卡 `192.168.12.1/24` | 无 |
| PC-B官方端 | RJ45 DHCP | USB网卡 `192.168.12.1/24` | 无 |
| PC-C客户端 | 可选，不承载本机视频专线 | RJ45 `192.168.12.2/24` | USB网卡 `10.77.0.1/24` |
| PC-D客户端 | 可选 | RJ45 `192.168.12.2/24` | USB网卡 `10.77.0.2/24` |

这种摆法通常需要4块USB网卡。路由器WAN能够上网时，PC-A赛事网卡可使用该路由器的网关；若另用手机供外网，则避免赛事网卡抢默认路由，按实际路由调整。12.x和10.77.x专线仍不填网关。

只有一对官方端/客户端时，去掉B/D与队友线即可。若引擎单独一台，`.1.2`只给引擎，两个官方端在1.x用DHCP；不把多台都设为`.1.2`。LAN口不够可在1.x层加交换机，但不要借它合并两条12.x专线。

路由器常见卡点：

- 改LAN后旧管理页断开正常；重新连接/获取地址，再访问 `192.168.1.1`。本机仍在31.x时先检查网卡地址。
- “上网设置”的静态IP是WAN，不是LAN。找LAN/内网/DHCP菜单；运营商锁定或中继模式下不能改时，换成能设置所需局域网的设备。
- WAN上级网络与1.x或12.x冲突时，协调上级路由或换一条可用外网，不能凭空填一个没有真实网关的新IP。
- 路由器恢复出厂会丢现有配置；先记录配置，按该型号说明处理，不把恢复出厂作为日常步骤。
- 外部WiFi若不能调整主控需要的网段，只能作为外网或普通测试网，不能冒充已完成整车裁判局域网。
- 手机USB共享断开会影响引擎外网；维护时检查手机供电、信号与省电设置。它不等于队友视频的专用网线。
