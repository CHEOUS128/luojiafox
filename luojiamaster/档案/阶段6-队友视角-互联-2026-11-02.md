# 阶段6 · 队友视角（2027 赛季两台自定义客户端互联）

> 2026-11-02。两台自定义客户端电脑之间拉一根额外的专用网线，各给对方转发一路「官方 UDP 图传的原始 HEVC」，
> 在客户端右上角的小窗里显示队友第一视角，可放大细看。
> **启用方式：双击 exe 即可，不需要任何文件、不需要任何参数。**
> 默认是 A 机（找 `10.77.0.2:47700`）；另一台点一下小窗标题条的 `[默认A]` 就切成 `[B]`（找 `10.77.0.1`），
> 选择会写回 exe 旁边的 `队友视角.ini`，下次打开一致。
> 想彻底关掉：`队友视角.ini` 里写 `peer=off`（`程序\关闭-队友视角.bat`），回到没这个功能时的样子。
> 命令行 `--teammate-peer/--teammate-listen` 仍然有效且优先（本地双实例测试就靠它）。
>
> **实车摆法（2026-11-02 CH 定）**：两台车 + 两台官方端电脑 + 两台客户端电脑，共四台。
> 两台客户端之间一根专用网线（`10.77.0.1` ↔ `10.77.0.2`，本节这套）；
> 每台客户端再和自己那台官方端各拉一根（`192.168.12.2` ↔ `192.168.12.1`）。
> 两根官方链路物理隔离，所以两个 `12.1` 不冲突。
> 现场接线/IP/启动顺序/判读表见 [`../局域网联调手册.md`](../局域网联调手册.md) 第十二节。

## 一、结论先放这

| 问题 | 答案 |
|---|---|
| 走哪条链路 | **TCP 47700**，两台机器各一段单向连接（A→B、B→A 互不依赖） |
| 传的是什么 | 官方 UDP 图传 `VideoShardsManager` 拼好的**完整 Annex-B 访问单元**，原样字节，不缩放、不重编码 |
| 为什么能原样传 | 客户端自带的 FFmpeg 8.1 只有解码器（h264/hevc/…），**没有 libx264/libx265**，本来也编不了；而且网线直连带宽富余，原样传画质 = 官方图传画质，放大 4 倍也不糊 |
| 谁解码 | 收端新写的 `TeammateVideoReceiver`（软解 hevc），和主链路的 `VideoDecoder` 完全独立 |
| 180° 倒置怎么处理 | 官方流在渲染层用 **GPU UV 翻转**显示；透传的是翻转前的字节，所以发送端把「我这边是否翻转」写进握手 + 每一帧头，收端照此画 |
| 按键 | `K` 折叠/展开 · `L` 接管/退出主画面 · L 模式下**滚轮** 1x~4x |
| 已占用不能碰的键 | `H` 主/副画面、`I` 翻转、`Esc` 比赛模式；`WASD Shift Ctrl QE RF GZXCVB` 会发给机器人；**CTRL 是整车复位**，任何新热键都不用 Ctrl |

## 二、线格式（`src/net/teammate_link.h`）

大端：

```
[握手 8 字节]  magic 'R''M''T''M' (0x524D544D) + version(1) + flags(1) + reserved(2)
[帧]          payload_bytes(4) + flags(4) + payload           // flags bit0 = 发送端画面是倒的
```

几个刻意的设计：

- **每帧都带 flags**：任一端按 `I` 切翻转，对面画面立刻跟着翻，不需要重连。
- **参数集补发**：VPS/SPS/PPS（HEVC NAL 32/33/34）由发送线程顺手缓存，每次重新连上都先补发一遍。
  否则晚启动的一端要等下一个 I 帧才有参数集，画面会黑很久。
- **有界队列**（深度 8，满了丢最旧）：队友链路永远不能反压主链路。丢帧只影响队友画面。
- **`TCP_NODELAY`** + 每次 1 秒重连 + 收发都设 2 秒 socket 超时（退出时能干净 join）。
- 监听端用**非阻塞 accept 轮询**（30ms）：Windows 上 `accept()` 在另一个线程里 `close()` 不会返回，
  阻塞版会在退出时把进程卡住。

## 四、布局与交互

- 队友小窗固定放在**右侧栏最上面**（宽度 = 屏宽 20%，高度按 16:9），BuffPanel 从它下面开始（中间留 6px）。
- **默认就画**，标题条：`队友视角` + 角色标签（`[默认A]` / `[默认B]` / `[A]` / `[B]`，点一下切角色）
  + 连接状态（`未连接 / 已连队友 / 队友已连入 / 双向已连`）。
- 只有 `队友视角.ini` 写了 `peer=off` 时整块才消失（不占 16:9、不占 47700、`K`/`L` 不注册）。
  老版本 ini 里没有 `peer=off` 时按默认 A 机启用——这样「把旧文件留在 exe 旁边」不会意外关掉功能。
- **K**：折叠只剩一条标题。
- **L**：直接画在 `GetBackgroundDrawList()` 上、压掉本车主画面，HUD 面板照常可见；
  左上角状态条显示 `队友视角 2.00x 已解 N 帧 翻转/正置`。再按 L 切回。
- **滚轮**：只在 L 模式下生效，1x~4x，中心放大（缩 UV 窗口）；同时吃掉滚轮，避免顺带滚日志面板。
- 所有按键都判断 `ImGui::GetIO().WantTextInput`，输入框打字时不会误触。

超时：1 秒内有新帧 = 在线（标题绿色）；5 秒内有 = 继续显示最后一帧；超过 5 秒 = 占位提示。

## 五、判据（第一次联调看这三处）

1. **两边都 `ping` 通**：A 上 `ping 10.77.0.2`、B 上 `ping 10.77.0.1`。
2. **标题条状态**：一端应显示「双向已连」（自己连上了对方 + 对方连进了自己）。
   只显示「已连队友」= 对方没开监听或防火墙挡了入站。
3. **日志里的「队友探针」**（每秒一行，只在启用时出现）：

```
队友探针 发=1234帧/5678KB 丢=0 队列=0 连=是 | 收=1200帧/5500KB 连入=是 | 解=1198帧 重建=1 错误=0 1280x720 peer=10.77.0.2:49812
```

判读：

| 现象 | 含义 |
|---|---|
| `发` 一直涨，对面 `收` 不涨 | 发送端在写，对面没收到 → 网线/防火墙/`队友视角.ini` 里的 `peer=` 填错 |
| `收` 涨但 `解=0`、`错误` 涨 | 码流不完整或版本不一致（两份客户端要同一版 exe） |
| `重建` 反复涨 | 参数集一直在变，通常是对端重开流或分辨率在切 |
| `丢` 持续涨 | 发送队列积压，队友链路跟不上（正常 4~8 Mbps 不应出现） |
| `队列` 经常满 | 同上，检查网线是不是走了百兆 |

## 六、防火墙

Windows 默认会拦入站 47700。**现成脚本**（两台客户端都要，右键管理员运行一次）：

```
程序\防火墙-放行客户端端口.bat
```

它加两条规则，可重复运行：`RM Teammate Video 47700`（TCP）、`RM Client UDP 3334`（UDP）。
**UDP 3334 是官方图传**，不是队友视频 —— 但自定义客户端那台电脑如果开着防火墙，
选手端推过来的图传会被拦掉，症状是「登录成功、主画面永远黑」。官方端 PC-2/PC-3 不跑这个。

手工等价命令：

```powershell
New-NetFirewallRule -DisplayName "RM Teammate Video 47700" -Direction Inbound -Protocol TCP -LocalPort 47700 -Action Allow
New-NetFirewallRule -DisplayName "RM Client UDP 3334"    -Direction Inbound -Protocol UDP -LocalPort 3334 -Action Allow
```

删掉：

```powershell
Remove-NetFirewallRule -DisplayName "RM Teammate Video 47700"
Remove-NetFirewallRule -DisplayName "RM Client UDP 3334"
```

> 注意：`netsh` 和 `New-NetFirewallRule` 加的规则**互不识别**（名字一样但一个是
> `netsh` 的旧格式）。混用的话 `show rule` 和 `Remove-` 各查各的，别以为没加上。

## 七、已知限制

- **（2026-11-02 修）默认启用那一版曾经一启动就白屏闪退。** 原因不在协议，在构造函数：
  「接收线程总是启动」的新代码和旧的 `if (listen_port != 0) { receiver_thread_ = std::thread(...) }`
  同时留在了 `TeammateLink` 构造函数里，等于给一个已经 `joinable()` 的 `std::thread` 再赋值 →
  标准库直接 `std::terminate()`，进程当场死，连构造函数最后一行日志都打不出来。
  日志停在 `队友画面解码器已启动`（它是紧前一步）、看不到 `队友链路已创建`，就是这个病。
  **判据：这两行日志必须相邻出现，中间断掉就是 TeammateLink 构造崩了。**
  改法：构造函数里只创建一次接收线程；发送线程创建包 `try/catch`，失败只降级成「只收不发」，
  绝不让主客户端退出。

- 只在「官方 UDP 图传有画面」的时候才有像素可转发。本车断图传，队友那边也会冻在最后一帧。
- 透传不保证不丢包：TCP 不会丢，但**发送队列会丢最旧的帧**（深度 8）。这只影响延迟，不会花屏。
- 没做身份认证：谁连上 47700 都能看。专用网线直连场景，够用。
- **CPU 占用没测过**：两台客户端都会同时解两路 1080p60 HEVC（本机官方图传 + 队友画面），
  都走 FFmpeg 软解。低电压轻薄本上可能出现主画面掉帧；`K` 折叠只停绘制、不停解码。
  实测时先看任务管理器，别等比赛里才发现。
- 没做加密：同上。
- 单客户端只支持一个队友（后连进来的会顶掉前一个）。

## 八、没网卡时怎么在本机验证（2026-11-02 补）

没有 USB 网卡、没有实车，也可以在一台电脑上把 UI、按键、相互连接全跑一遍。

### 需要的文件（都在 `程序\`）

| 文件 | 作用 |
|---|---|
| `启动-本地测试-A.bat` | A 实例：视频口 3334，队友监听 47700，连 47701 |
| `启动-本地测试-B.bat` | B 实例：视频口 3335，队友监听 47701，连 47700 |
| `测试-本地视频源.bat` | 本地假图传：读 `测试画面.h265`，按固件格式发 UDP |
| `测试画面.h265` | 测试码流：真实官方图传抓包里抽的 120 帧 1080p HEVC（2.0MB） |

**不需要 ffmpeg。** 第一版是拿 ffmpeg 现场生成画面（`testsrc2` / `smptebars`），
好处是能一眼分出 A/B 两路，代价是每台机器都得装一个带 libx265 的 ffmpeg，实测当场就卡在这一步。
现在改成**直接回放真实抓包的字节**：`测试画面.h265` 是从
`程序/logs/20261025_192645_687/network_capture.bin` 里，找第一个带 VPS/SPS/PPS 的帧（第 70 帧）起，
取连续 120 帧拼出来的，**原封不动的官方 HEVC 字节**（1920×1080、12.19 分片/帧、峰值 220KB 的 I 帧也在里面）。
这比 ffmpeg 版更接近实车：大帧、参数集重复、1080p 全都有，只用 Windows 自带的 PowerShell，零依赖。

### 步骤

1. 双击 `启动-本地测试-A.bat` 和 `启动-本地测试-B.bat`，两个窗口各开一个客户端。拖开、各占半屏，方便看。
2. 各发一个 `测试-本地视频源.bat` 窗口：A 不用带参数（发 3334），B 带 `3335`。
   两路画面一模一样（同一段码流），这正常 —— 要分得清是哪一路，看两个客户端各自的主画面。
3. 两个客户端里各点「登录 / 进入比赛」——视频流**不登录也会接收解码**，但主画面要进比赛模式才铺满。
   本机没有裁判系统，登录按钮**点了也不会进去**（绿色「登录」会一直是亮的）；直接**按 `Esc` 就是进出比赛模式的开关**。
4. 右上角新出现「队友视角」小窗，标题条应是**绿色 + 双向已连**，画面 1 秒内出图。

> **点哪个窗口，键鼠就只发给哪个。** 两个实例里控件名一模一样，**先把鼠标点进 A 的窗口再操作 A**，
> 否则点下去的是 B 的按钮（ImGui 同一帧里同名控件会被当成同一个，A 那份会被跳过）。
> 拖动分隔条时也一样：在哪个窗口里按下，就在哪个窗口里生效。

### 本机测试判读

| 现象 | 含义 |
|---|---|
| 两个窗都开了，标题条还是「未连接」 | 队友端口填错，或防火墙拦了入站 47700/47701。`netstat -ano` 里应看到 47700 和 47701 各一个 `LISTENING` |
| 标题条「双向已连」，小窗一直黑 | 假图传没在发。视频源窗口应每 5 秒打印一行 `sent N frames`；A 发 3334、B 发 3335，别弄反 |
| 主画面有图、小窗黑 | 本机图传正常，只是 TCP 那一路没通 —— 看标题条颜色，和日志「队友探针」的 `收=` 有没有涨 |
| 小窗有图，但 K / L / 滚轮没反应 | 鼠标不在那个窗口里，先点一下窗口再按键 |
| 刚启动第 1 秒黑一下才出图 | 正常。这段码流第一帧就是 I 帧，到了才出图 |
| 画面像慢了半拍、有拖影 | 正常。`测试画面.h265` 是从真实图传里抽的**运动画面**，不是静态图 |

### 为什么两个实例要错开端口

Windows 的 `SO_REUSEADDR` 不会挡住两个进程同时绑同一个 UDP 端口，后绑的那个只收得到一部分包。
所以 A 听 3334 / B 听 3335，视频源也按端口分开发。队友链路同理：47700 / 47701，互相连对方的。

MQTT 指向 `tcp://127.0.0.1:3333` 是故意的：本机没人监听，连接会在 5 秒后超时重试，
客户端照常刷新，不会去连 192.168.12.1 上不存在的裁判系统。

两个实例的窗口类名都是 `luojiamaster`，互不冲突：Windows 的窗口类按进程注册，
`CreateWindow` 用的是本进程的 WNDPROC。**键鼠只发给被点中的那个窗口**——
点了 B 再按 `K`，只有 B 折叠；A 的键鼠也不会重复发给机器人。

### 假图传的格式（和固件一致）

```
每个 UDP 包：frame_id(2B 大端) | shard_id(2B 大端) | frame_bytes(4B 大端) | 分片数据
```

按 HEVC 的 access unit 切（一个 VCL NAL 开一帧，后面的 SEI/参数集跟在这一帧里），
`shard_id` 从 0 连续，`frame_bytes` 是整帧字节数。客户端侧要满足三个条件才会拼帧：
分片连续、`collected_frame_bytes == frame_bytes`、每个分片大于 8 字节。
本地源按 1332 字节一片发。这段 1080p 码流共 1609 包 / 120 帧，
30 帧/秒 时约 **400 包/秒、5.1 Mbps**，和实车抓包实测的 57fps / 12.19 分片每帧同量级。

> 码流是按 `00 00 01` 切 NAL 的。**切出来的 120 个访问单元逐字节拼回去，和原码流完全一致**
> —— 这个我用脚本验过（`AU 120 / 重组 120 / 逐字节一致 True`），不是靠猜。
> 中间的起始码是 4 字节（`00 00 00 01`）的 NAL，前面会多带一个 `00`，
> HEVC 解码器把它当作 `zero_byte` 前缀，合法，不影响解码。

第二节说的「不需要 ffmpeg」也适用于这里：发送端只做切分和发 UDP，不做任何编码，
所以 Windows 自带 PowerShell 就够了。

### 想给 B 换一张脸时

`测试-本地视频源.bat` 只认 `测试画面.h265` 一个文件。要两路画面不一样，最省事的办法是**再抽一段**：
换一个抓包（`程序/logs/` 里任意一个 `network_capture.bin`），照同样的规则抽 120 帧存成 `测试画面-B.h265`，
再把 B 那份 bat 里的 `set "SRC=%~dp0测试画面.h265"` 改个名。抽帧脚本每次都要现写，
不如直接加一个 `SFX` 参数 —— 需要的话跟我说，两分钟的事。

## 九、硬约束：新功能不能让原有功能变差（2026-11-02 CH 定调）

CH 的原话：**「这个新功能不能让之前已有的功能效果变差。」**
后来又补了一句更硬的：**「我不是说了要点了就能用吗。」**

两句合起来是最终形态：**默认就启用（双击 exe 就有，不放文件、不传参数）**，
关掉要显式在 ini 里写 `peer=off`。判据是：**默认状态下，新增开销必须可数；
显式关掉后必须回到「没这个功能」的原样。**

| 可能的「变差」 | 怎么保证 | 代码位置 |
|---|---|---|
| 多占显存 / SRV 槽位 | 队友纹理**第一次上传才创建**，没收到帧就永远不存在 | `windows_platform_backend.cpp` `UploadDynamicTexture` |
| 多解一路 1080p | `TeammateVideoReceiver` 只在链路建起来时构造；`peer=off` 时不构造 | `application.cpp` `BackgroundServices` 构造函数 |
| 线程空转 | 发送是阻塞 `wait_for(100ms)` 队列等待；接收是 30ms 轮询 accept（Windows 上 close 不唤醒阻塞 accept，轮询是退出必需的）。没有忙等 | `teammate_link.cpp` |
