## 一、最终摆法（CH 2026-11-04 口述，本阶段以此为准）

四台笔记本的硬件前提**完全一样**：**1 个自带方形 RJ45 网口 + 1 块无线网卡 + 若干 USB 口**。

1. **四台电脑 + 两台机器人的主控，全部用无线网卡连同一个 WiFi**（路由器当赛事服务器）。
   路由器上一个网线口都不插。
2. **官方链路走「自带网口 ↔ 自带网口」**：PC-A 自带网口 —— PC-C 自带网口；
   PC-B 自带网口 —— PC-D 自带网口。
3. **只有 C↔D 的队友链路用 USB 转 RJ45 网卡**：两块 USB 网卡 + 一根网线。
   所以 **USB 网卡只需要买 2 块**，A/B 一块都不用。
4. **PC-A 的外网靠手机 USB 共享**（官方方案 2 的双网卡形态）。

```
WiFi 路由器 192.168.1.1
   ├─ 无线 ─ PC-A（引擎+步兵选手端）  以太网 12.1 ──网线── PC-C 以太网 12.2
   │            └ USB 手机共享（外网）
   ├─ 无线 ─ PC-B（英雄选手端）        以太网 12.1 ──网线── PC-D 以太网 12.2
   ├─ 无线 ─ 步兵主控
   └─ 无线 ─ 英雄主控
                              PC-C USB 10.77.0.1 ══网线══ PC-D USB 10.77.0.2
```

> 两条 `12.x` 网线物理上互不相连，所以「两个 `12.1`、两个 `12.2`」同时存在不冲突。

## 二、这份摆法是怎么定下来的（两次更正）

### 更正 1（2026-11-03）：路由器没外网也能开引擎

我原先以为「路由器 WAN 没网 → 引擎外网测试必红」。CH 纠正：
「再插一个 USB 连手机共享网络就能上外网」。核对官方《赛事引擎联网操作手册》（202604）后确认，
这正是手册里的**「方案 2 · 双网卡」**：

> 「使用两张网卡，一张来自主机本身的无线网卡，另一张可来自另外购置的外置网卡或主机本身的有线网卡。」
> 「对于希望连接广域网（互联网/外网）的网卡，设置为自动获取。」

现在文档口径：**路由器可以不联网，外网由 PC-A 的 USB 手机共享提供。**

### 更正 2（2026-11-04）：网卡落点全反了，USB 网卡只需 2 块

我原先写的落点是「PC-A 主板网口 `1.2` + USB 网卡 `12.1`，官方端各要一块 USB 网卡，一共 4 块」。
CH 更正：四台笔记本都自带 RJ45，**官方链路应该走自带网口**，USB 网卡只给 C/D 当队友线。
连带后果：

- **USB 网卡 4 块 → 2 块**（只给 PC-C / PC-D），物料清单已改
- 客户端的落点反过来：**自带网口 `12.2`（朝官方端）、USB 网卡 `10.77.0.x`（朝队友）**
- PC-A 的 `1.2` 落到 **Wi-Fi 网卡**上（因为唯一的有线口去跑 `12.1` 了）
- PC-A 只有一块无线网卡，已经连路由器，**外网只能走 USB**，不能同时连手机热点

## 三、这次的真正约束：每台机器哪块网卡跑哪件事

| 机器 | 网卡 | 跑什么 | 地址 | 网关 |
|---|---|---|---|---|
| **PC-A** | Wi-Fi | 赛事局域网 + 引擎 | `192.168.1.2/24` | 空 |
| | 自带 RJ45 | 官方链路 → PC-C | `192.168.12.1/24` | 空 |
| | USB（手机共享） | 外网 | 自动 | 自动 |
| **PC-B** | Wi-Fi | 赛事局域网 | DHCP | 自动 |
| | 自带 RJ45 | 官方链路 → PC-D | `192.168.12.1/24` | 空 |
| **PC-C / PC-D** | Wi-Fi | 可不连 | — | — |
| | 自带 RJ45 | 官方链路 → 自己的官方端 | `192.168.12.2/24` | 空 |
| | USB 转 RJ45 | 队友链路 | `10.77.0.1` / `.2` | 空 |

**网关策略**：除了手机共享那块，其余网关**全部留空**。
这样 `route print` 里 `0.0.0.0 0.0.0.0` 只有一条，引擎的外网测试自然走对，跃点数都不用动。
（官方方案 2 的跃点数 20/10 只在「两块都带网关」时才需要。）

## 四、本次补上的两个实际卡点

### 1. 客户端防火墙默认拦入站 ping

`防火墙-放行客户端端口.bat` 原先只放行 TCP 47700 + UDP 3334。
Windows 防火墙默认**拦入站 ICMP 回显**，结果是：
队友线 IP 都配对了、视频链路其实也通，但 `ping 10.77.0.x` 一端通一端不通，
现场会误判成「网线/IP 配错」。

处置：
- `程序\防火墙-放行客户端端口.bat` 新增第三条规则 `RM ICMP Echo`
  （`protocol=icmpv4:8,any`），并在说明里写清楚「ping 不通但视频可能正常」
- `程序\现场自检-四台电脑.bat` 第 5 节同步检查这条规则（缺失打 `[--]` 不是 `[!!]`）

### 2. 客户端主画面「全黑」最常见的原因是 UDP 3334

这条以前只在档案里写过，现场手册里单列成排查项：
选手端往客户端推图传是 **UDP 3334 入站**，客户端防火墙没放行 → 登录成功但主画面永远黑。
官方端则相反：官方手册要求**关闭本机防火墙**（原文「关闭本机防火墙」），
所以官方端不能跑这个脚本，要整机关掉。

## 六、现场判据（三条最短的）

1. `route print` 里 `0.0.0.0 0.0.0.0` **只有一条** → 引擎两项测试才会绿
2. `ping 192.168.12.1` 在自己那台客户端上通 → 官方链路成立
3. `ping 10.77.0.x` **双向**通 + 小窗标题条「双向已连」→ 队友链路成立
   （只要「有画面」不算数：两台都是 A 机时显示的是自己的车）

## 七、未验证 / 待 CH 现场确认

- **引擎主机走无线连路由器**：官方手册推荐有线，并在方案 1 写「请勿使用无线方式连接裁判端主机与无线路由器」。
  这套摆法里 PC-A 的唯一有线口被官方链路占了，所以只能走无线 ——
  主控心跳和「本地 IP 配置测试」可能偶发失败，现场多点两次。这是目前唯一的硬妥协。
- 手机 USB 共享在 CH 那台手机上是否稳定（安卓 USB 网络共享通常比 Wi-Fi 热点稳，
  但省电策略可能掐断），需要现场点一次引擎「外网连接测试」才算数。
- 两块 USB 网卡长时间跑 TEAMMATE 链路（4~8 Mbps TCP）会不会发热掉线，未实测。
- 四台电脑 + 两台主控六台设备挤在一个 2.4G 信道上，图传 UDP 的丢包率未实测。
