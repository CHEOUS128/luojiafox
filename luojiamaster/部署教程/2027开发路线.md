# luojiamaster 开发路线

**2026 年 11 月 21 日｜2027 超级对抗赛操作手已接入第一批岗位菜单。步兵选底盘，重装看装配，两个岗位都能看回血和复活。** 首页仍是同一个 Windows 程序。队员先选赛事、再选岗位。本队优先高校联盟赛（RMUL）3V3，超级对抗赛（RMUC）7V7 有独立入口和指挥席。日常操作看[客户端 README](../README.md)，换电脑看[部署教程](README.md)。

## 一、已经实现的功能

三个赛事的操作手都能按 M 看全场。7V7 已有随车录像、比赛顶栏和赛况提示，这一节点补上重装与步兵的 Esc 菜单。[操作手地图实图](../档案/配图/7V7操作手地图.jpg)

### 现在每个入口能用什么

| 入口 | 队员现在能用的功能 | 已验证到哪里 |
| --- | --- | --- |
| 三个赛事共用 | 操作手的正式登录和本地测试进入同一套比赛界面。本车可切主副画面、手动翻转官方图传、开关菜单、按 F11 全屏。正式入口缺图时显示等待，本地测试用实录过原收包、解码和显示流程 | Windows 上用交付程序验证过窗口、全屏、播放和返回。本车视频稳定性、故障恢复及旧版长测的观察项见[客户端档案](../档案/README.md) |
| 2026 超级对抗赛 | 保留原登录、比赛菜单、地图、本车双路视频。操作手可用与 2027 共用的队友查看方式，互看岗位为 1、3、4 号。M 大图使用 2026 当年底图；本地回放复用两张随车小窗 | 2026 全向轮步兵曾跑通工业相机到客户端的正式视频链路，旧版队友互看有实车记录。新岗位配对的验证范围是本机多身份测试 |

| 2027 超级对抗赛操作手 | 重装、步兵按 M 看完整二维场馆，本地回放有双方样例位置、两张队友随车小窗和断流测试。平时显示 2027 超级对抗赛小地图，红蓝双方操作手均以己方在左侧查看。右侧两路上下排列，K 收起或展开，L 切到左右并排，单击一路单独放大，再点返回。2026 也能试同一套操作。联盟赛按 L 只放大唯一队友 | 三个赛事都用本地实录检查过 F11 和队友视角。本机三个身份验证过相互发现、晚登录、断开及重连 |
| 2027 超级对抗赛指挥手 | 本地单屏看三位队友。默认小窗随己方同号棋子移动，可就地放大、缩回和切换；顶部可选原左右分栏。一路断开时在原位等待，其余两路继续。点一路看大图，返回时保留地图位置、角度和倍率。左右键、滚轮各自只作用于对应区域 | 三路是已有实车录像的独立回放。当前岗位通过「本地测试」进入。[随车小窗实图](../档案/配图/7V7指挥席.png) |
| 指挥席地图 | 默认俯视全场。滚轮放大后可绕基地角或高台换角度，旋转时倍率固定。场馆可一键回到俯视。缺三维模型时用二维底图。八枚红蓝棋子按场地比例绘制，旁边的号码正立。样例位置超过 3 秒未更新变淡，到 10 秒隐去 | 用同一组地标检查过两种三维、二维和缺模型回退。三处固定地标缩放三格，最大漂移小于 1 像素。地图标注「位置：本地样例」，2027 裁判位置还没有现场证据。[导航测试](../源码/tests/commander_nav_test.cpp) |

**2027 超级对抗赛公共赛况。** 操作手首屏显示局数、阶段、计时、比分、双方累计控制度、两座基地、R/B 两座前哨站和双方八台车的血量。阵地变化等短消息居中显示在倒计时下方，暂停时倒计时停住，结算采用裁判给出的胜者和原因。基地满血 10000，前哨站满血 1000；R/B 表示固定地点，换到蓝方这两个值仍在原处。零血量与尚未收数分开显示。指挥席顶部可以查看本地样例的同一份局数、时钟、比分和结算。

**7V7 岗位状态。** 重装 1 显示己方科技等级和最近一次全场装配通报，步兵 3、4 显示裁判回传的本车底盘配置。Windows 已用本地赛况核对六个红蓝岗位，并在 1080p 全屏查看重装 1 和步兵 4。

**7V7 岗位菜单。** 步兵在准备和自检阶段可选底盘，开赛倒计时、比赛、暂停和结算期间锁定。重装按裁判公开的核心位置、可选难度和装配状态展示赛中申请。两个岗位按裁判许可和己方金币显示回血或复活，远程回血价格按表 5-7 计算，付费复活直接读裁判报价。性能同步消息没有申请编号，界面用「回传值一致」表示收到的底盘值与申请一致。全场装配事件没有队伍和申请编号，因此单独展示。规则依据为 RMUC V1.0.0 §5.3、表 5-7、§5.4.3、§5.5.2、§6.3～6.6。通信协议 V1.0.0 对应 §2.2.3、§2.2.5、§2.2.7、§2.2.9～11、§2.2.21～25。[比赛规则](https://bbs.robomaster.com/wiki/20204847/1969149) · [通信协议](https://bbs.robomaster.com/wiki/20204847/1969151)

本地互动局现在是 64 秒，六个红蓝岗位的数据均已核对。原 39 秒样例继续用于原有回归。队员的 [F11 与 Esc 验收步骤](../README.md#按-esc-试一遍-7v7-岗位菜单)给出了能看到的变化及时间。2027 官方端验证另行安排。

版本校验和本机实测以[客户端 README](../README.md#当前版本和验证范围)为准。历次录像的结果和未通过的项目见[实测与排错经验](../档案/README.md)。

## 二、当前开发顺序

**先在 Windows 上把比赛功能做完整，再用同一份源码交付原生 Linux 比赛版。** 2027 制作规范 S60 和官方答疑 #347 明确，自定义终端使用的操作系统也须开源。队内继续在 Windows 上开发、演示和联调，2027 比赛电脑按 Linux 准备。新写的赛况、岗位和界面代码由两端共用，涉及操作系统的窗口、显示和文件操作集中在各自的平台代码里。[2027 制作规范](https://bbs.robomaster.com/wiki/20204847/1969150) · [官方答疑 #347](https://qingflow.com/appView/g79clgn1kk02/shareView/g79clh9dkk02?applyId=801859841)

### Windows 下一节点：补齐其余岗位菜单和一整局流程

| 顺序 | 接下来做什么 | 怎么验 |
| --- | --- | --- |
| 1．补齐其余岗位菜单 | 底盘、装配、回血和复活已接入。2027 其余机关配置和弹量兑换等待逐项核对规则、适用岗位、开放阶段及返回状态。 | 遍历红蓝两方的三个岗位。选项出现在对应岗位和阶段，超时、缺字段和重复同步能区分。 |
| 2．补齐一整局 | 已有准备、自检、倒计时、暂停、恢复、结算和换局的本地样例。下一步补中途加入、失联重连、平局和异常结束。 | 断掉一类数据后能看出哪一项失联。重连后跟到当前局，上一局的提示及血量不会留在画面上。 |
| 3．核对指挥席正式身份 | 按官方规定确认该席位如何登录、允许看到哪些比赛数据，再接正式单屏。两块屏的布局放到后面。 | 确认正式身份后才显示已登录。缺一路视频仍可读赛况，缺三维场馆仍能看二维地图。 |

公共赛况按 2027 比赛规则 §5.6.1、§5.8 及通信协议 §2.2.3、§2.2.4、§2.2.7 对齐。2027 事件 7 表示 R 基地阵地归属变化。2026 继续按当年规则解释。 [比赛规则](https://bbs.robomaster.com/wiki/20204847/1969149) · [通信协议](https://bbs.robomaster.com/wiki/20204847/1969151)

**指挥席正式身份。** 规则表 3-2 规定指挥手席位，§3.3.1 限定自定义终端可接收的赛事信息；§4.5.3 为重装与指挥手额外提供的 HDMI 屏可选用。协议第 46 页要求按连接的机器人填写客户端 ID。正式候选版应接好身份选择、等待、失联和本席可见性。缺乏官方确认时明确标“正式身份待联调”。本地演示身份、设备编号或“已连上服务器”都不能作为登录成功证据。

### 怎么逐步验收

1. **公共界面已在本机验证。** 在 1080p 全屏，本地红方重装和正式入口连接本机模拟服务的蓝方步兵读到了相同的建筑血量；六个操作手岗位另通过自动测试。2027 官方端仍待联调。
2. **再验齐各个岗位。** 红蓝两边各走一遍重装、步兵 3 和步兵 4，指挥席单独测。包括中途加入、暂停恢复、局末平局、重复或顺序不同的消息、单路缺失、失联重连及阵营切换，再检查 2026 和联盟赛。F11 实按全屏，同时检查大窗口、明暗画面的可读性和现有 12 项回归。若改动视频显示，用同两路实录复测每路的新画面数和最长停顿。
3. **集中现场核验。** 公共界面、岗位内容和比赛流程在桌上验齐后，再排机时。2026 官方端验证共用的真实连接与既有功能；2027 官方端到位后，按岗位确认真实登录、实际收到的数据、限制显示及完整比赛流程。分别记录“本地已验”“正式入口接本机服务已验”“对应赛季官方端已验”。得到对应赛季和岗位的现场证据后再列为赛用已验。

## 三、基础版之后的优化

### 3V3 控制度掉点留影（已列入规划）

沿用双方现有控制度条。收到新数值时，数字和实色条立即更新，刚扣掉的那一小段保留约半秒淡影，随后消失。连续小幅扣点时只更新同一道淡影。首次收到数据、重连补发、换队和新局直接定位到当前值。用逐秒扣点、一次扣 10、降到零和中途登录四种情况在 F11 下验，避免把首次加载误画成掉点。

### 7V7 阵地强化展示（已列入后续规划）

限 2027 超级对抗赛。规则 §5.6.2 把四处阵地分成两对。控制两处前哨阵地的一方每秒增加 1 点控制度，控制两处基地阵地的一方每秒增加 3 点。基地被毁先按基地剩余血量判胜负；时间到且双方基地均存活，先比累计控制度。结算采用裁判结果。[比赛规则 §5.6.1、§5.6.2、§5.8](https://bbs.robomaster.com/wiki/20204847/1969149)

| 队员看哪里 | 画什么 |
| --- | --- |
| 视频上方 | 红蓝基地沿用血条，两队累计控制度以大数字放在倒计时两侧。时钟下方用四个小标记分成前哨、基地两对。两处同属一方时，同对标记间点亮细线并标该组规则收益（前哨 +1/秒，基地 +3/秒）。官方累计数单独更新。 |
| 右下小地图 | 在 R 前哨、B 前哨、R 基地、B 基地的固定地标上画四枚小标。R/B 表示开局地标，阵地易主后仍叫原名。标签色表示当前控制方，实框表示完全控制，虚框表示临时控制。未收到显示灰色问号。 |
| 按 M 的二维大图 | 放大同四枚标记，展开“地名 · 红/蓝方 · 临时/完全”。各前哨可另显示站体血量。前哨阵地对应前哨站和中央高地两处增益点，基地阵地对应基地和堡垒两处增益点，详图用同一标号关联。保留地形轮廓，避免把两点之间的地面涂成虚构边界。队友录像避让地名。 |
| 指挥席 | 二维和三维使用同一份阵地状态。三维标签落在对应地标，转图时文字正立。开局地点、当前控制方、建筑血量各自独立。优先做好操作手二维版，再复用到指挥席。 |

**细节。** 两个前哨阵地各有红/蓝临时和红/蓝完全四种状态。基地阵地只有初始拥有方能完全控制，对方只能临时控制。临时控制也用所属方颜色，建筑保留单独图标。正处于激活过程时，只有该席收到对应计时才显示小弧和方向。时间参数为零表示进度无变化。中途登录先用全局状态还原四处归属；短提示只在确认变化时出现一次。缺项显示“待更新”，明确收到 0 分显示 0；断流后撤掉实时收益提示，换局清空旧状态。

**数据。** 通信协议 §2.2.4 的 `GlobalUnitStatus` 提供双方累计控制度、固定 R/B 前哨站血量以及四处阵地状态。R/B 前哨固定按地点，己/对方按登录阵营换算。§2.2.6 的 `GlobalSpecialMechanism` 提供激活计时，§2.2.7 的 `Event` 提供阵地变化提示。状态包的前哨编码按己方/对方，事件参数按红方/蓝方，两者分开解释。2026 的护盾、建筑状态与旧事件另走当季解释。蓝方操作手转图，地点、两处关联标记和地名一起转，文字保持正立。正式席位的数据覆盖和中断后的表现待核对。[通信协议 §2.2.4、§2.2.6、§2.2.7](https://bbs.robomaster.com/wiki/20204847/1969151)

**本地验收。** 实施这项优化时，在同一帧实车录像上给出“开局各持两处”和“蓝方临控 R 前哨”两张全屏设计图。确认后用标注为样例的赛况测红蓝换边、计时停住或倒退、临控与完全切换、血量单独变化、同对归属与累计分不同步、断流重连和新局。蓝方登录时，分别用全局状态和事件描述同一次归属变化，三个界面必须显示同一地点、同一方。两种亮度的录像下检查 1920×1080 全屏及大窗口，再同片复测两路画面的更新数和最长停顿。现场联调集中在界面功能齐备后进行。

### 重装、指挥手双屏及其他增强

重装可把工业相机放到副屏，指挥席可将单屏中的两个部分拆到两块屏。等单屏版完成后，再实接 1080p HDMI，测试不同缩放、全屏、拔屏回主屏、重新接上和下次启动。单屏与双屏使用同一套赛况和席位显示规则。指挥席更多布局与队内提醒留在该岗位基础版之后评估。

## 四、部署复现与赛前验收

### 功能齐备后，让队员在另一台电脑独立试一局

从 GitHub 下载并解压，按[部署教程](README.md)在另一台 Windows 电脑做一次十分钟左右的本地验收。建议让没参与开发的队员自己操作。

1. **先验主赛项 3V3。** 选联盟赛步兵 3，按 F11、H、M、Esc。队员能切主画面、看到完整联盟赛地图，关图后回到自己选的视频。
2. **再验 7V7。** 选超级对抗赛蓝方步兵 3，按 L、M，点击蓝 1 和蓝 4 的录像，再按 Esc。应回到原来的双画面。断开一路本地录像，另一格应继续更新。
3. **验收看队员能否独立完成。** 记下首次卡住的按钮、缺的文件或看不懂的叫法，先修说明或入口。桌上通过后再集中排实机复测。

联盟赛继续按静态图验收。此前查阅的《机器人制作规范手册》印刷第 47 页说明 RMUL 无需安装定位模块，目前尚缺普通操作手席位的正式位置数据。[联盟赛规则](https://bbs.robomaster.com/wiki/20204847/1969150) · [通信协议](https://bbs.robomaster.com/wiki/20204847/1969151)

### Linux 比赛版怎么验

窗口和视频已有 Linux 代码，当前版本只在 Windows 做过整机界面实测。Linux 的 F11 全屏需要接入，指挥席三维场馆目前会退回二维；仓库现成的 Linux 视频库适用 x86-64。选定比赛电脑后再核对处理器、显卡和驱动。

1. 在比赛用 Linux 电脑上原生编译并从桌面启动，先过主赛项 3V3。用和 Windows 相同的录像验双路出图、F11 全屏、M 开图、Esc 返回、暂停和换局。对比每路实际显示帧数和最长停顿。
2. 接着验 7V7 各岗位的界面、中文、赛事切换与指挥席三维。确认比赛机实际画出了三维场馆，能带着三路录像运行。
3. 软件功能验齐后，再集中接对应赛季官方端核对身份、赛况和图传。Linux 桌面测试和正式端现场结论分别记录。

### 赛前集中验证与回退

两台、三台实体电脑的岗位互看安排在基础界面验齐后；指挥席第四台电脑与其正式身份一起核验。优先借 2026 条件检验通用功能，再按 2027 对应版本的官方输入核对各席实际显示。冻结前用实际比赛电脑走完准备、开局、暂停、结算、换边和下一局，留存上一个可用版本与校验值。未验证的赛季、席位和设备分别列明。
