## 0. 一句话说明这是什么

`luojiamaster` 是 RM26 赛季「自定义客户端」的实现。它替代官方选手端，接入官方赛事引擎体系，完成三件事：

1. **接收比赛数据**（血量、时间、经济、增益等 25 个 MQTT topic）
2. **接收机器人第一视角图传**（UDP 3334，HEVC 1080p60）
3. **发送键鼠控制指令**（MQTT `KeyboardMouseControl`，75Hz）

## 1. 关键结论（先看这节，能省掉大量试错）

以下每一条都是实测验证过的，不是推测。**改动任何一条前请先理解为什么。**

### 1.1 必须用新版官方选手端

| 版本 | 结果 |
|---|---|
| `RoboMasterClient 12.0.0.30`（RMUL 3v3，2026-02） | ❌ **不可用**。程序内有 `MQTTServer.cs`/`StartServer` 代码但未启用，`netstat` 查不到 3333 监听，P 设置面板没有「键鼠控制来源」选项 |
| `RoboMasterClient 12.0.0.213`（RMUC 学生版，2026-07） | ✅ **可用**。启动后自动监听 `0.0.0.0:3333`（MQTT Broker），P 面板出现「键鼠控制来源」，可选「自定义客户端」 |

**官方更新日志原文**：
> 【2026超级对抗赛学生版-V1.2】修复选手端自定义客户端无法控车的问题

**这是整个项目能不能跑起来的唯一分水岭。** 旧版无论怎么配网络都无解。

### 1.2 学生版赛事引擎不提供 MQTT

对 `RoboMasterEngine 12.0.0.34` 与 `12.0.0.137` 做过全目录搜索：
- `RMServer.exe` / `AdapterSvrS0.exe` / 全部 DLL / 全部 Lua 脚本中**没有任何 MQTT 服务器实现**
- 它只监听 S0/S1 TCP/UDP GateSvr（如 `15861` / `15862`），是官方选手端专用二进制协议

**结论：不要试图让自定义客户端直连引擎，连不上。必须经过官方选手端。**

### 1.3 完整链路

```
┌─────────────────────┐
│ 裁判端电脑           │  RoboMasterEngine.exe
│ (赛事服务器)         │  局域网网卡静态 IP: 192.168.1.2
└──────────┬──────────┘
           │ 局域网（同一网段即可，实测同 Wi-Fi 也行）
           ▼
┌─────────────────────┐
│ 选手端电脑           │  RoboMasterClient.exe（12.0.0.213）
│                     │  ① 登录引擎并正常显示图传（硬性前提）
│                     │  ② MQTT Broker 监听 0.0.0.0:3333
│                     │  ③ UDP 3334 推送 HEVC 图传
│                     │  ④ USB VCOM（COM5）→ VT13 接收端 → 无线 → 车
└──────────┬──────────┘
           │ MQTT 127.0.0.1:3333（同机）或 选手端IP:3333（异机）
           │ UDP  3334
           ▼
┌─────────────────────┐
│ luojiamaster        │  登录填 127.0.0.1:3333
│ (自定义客户端)       │  机器人 ID 必须与选手端一致
└─────────────────────┘
```

**四条硬性前提**（缺一不可）：
1. 选手端版本 ≥ `12.0.0.213`
2. 选手端已登录引擎，**且图传画面正常显示**（官方手册原文：只有图传正常时才会向外推送视频流）
3. luojiamaster 与选手端登录**同一个机器人 ID**
4. 选手端 P 面板 → 键鼠控制来源 → 选**自定义客户端**

## 2. 快速上手（已有 exe，直接运行）

### 2.1 运行环境

- Windows 10/11 x64
- 无需安装 FFmpeg（已静态链接进 exe）
- 无需其他运行库

### 2.2 启动步骤

1. **裁判端**（另一台电脑）：网卡设 `192.168.1.2`，启动 `RoboMasterEngine.exe`，登录，开始使用
2. **选手端**（本机或另一台）：启动 `RoboMasterClient`，登录引擎，**确认图传画面正常**，P 面板把键鼠控制来源切到「自定义客户端」
3. **luojiamaster**：双击 `程序/luojiamaster.exe`
4. 登录页填 **`127.0.0.1:3333`**（选手端同机）或 **`选手端IP:3333`**（异机）
5. 选队伍、选机器人（**与选手端一致**），点登录
6. 进入比赛界面后按 **Esc** 进入比赛模式，即可用 WASD + 鼠标操控

### 2.3 快捷键

| 键 | 功能 |
|---|---|
| `Esc` | 进入 / 退出比赛模式（**只有进入后才会发送键鼠**） |
| `H` | 主画面 / 第二视角（本车视频）切换 |
| `I` | 主画面 180° 翻转（GPU 实现，无性能开销） |
| `P` | 设置面板（鼠标灵敏度 0.05~3.0） |

> **① 必须加 `-DFETCHCONTENT_FULLY_DISCONNECTED=ON`。**
> `CMakePresets.json` 和 `一键配置与编译.bat` 里**都没有**这个参数。不加的话

> 新开的 PowerShell 窗口**不继承** dev shell 的环境变量。症状很好认：
> 所有 `.obj` 都编译成功，最后链接报
> `LINK : fatal error LNK1181: 无法打开输入文件"oleaut32.lib"`——
> **不是代码问题**，是 `LIB` 里缺 Windows SDK 的 `um\x64`。
> （`cmake --preset` 配置阶段在普通窗口能跑通，只有 build 阶段需要。）

```powershell
# 2. 配置（首次；★ 必须带 FULLY_DISCONNECTED）
cd ..

# 3. 编译
cmake --build --preset release
```

```powershell
# 4. 覆盖仓库里的那份（它是唯一入库的二进制，必须同步）
```

> `Get-Item C:\rm26build | Select-Object Target`

### 3.4 中文路径必读（重要）

ACE 工程放在含中文的路径下会触发 MSVC 链接器 `LNK1181` 乱码错误（响应文件按 GBK 读取，内容为 UTF-8）。

**解决办法：建一个 ASCII 短路径 junction（目录联接）指向工程目录，在其中编译。**

```batch
mklink /J C:\rm26build "D:\你的路径\含中文\工程目录"
cd /d C:\rm26build
cmake --preset release
cmake --build --preset release
```

junction 只是指针，实际文件仍在原目录，不会额外占用空间。

> ⚠️ **junction 必须指向仓库里的 `luojiamaster/源码`。**
> 仓库里还有另一份 `自定义客户端\编译工作区\ACE_RM26_CustomClient`，
> 那是旧的、**已经过期**的工作区。曾经把 junction 指到那边，
> 结果「改的是 `源码/`、编译的是旧目录」——改了半天不生效，白折腾一晚上。
>
> **每次改代码前先确认一次：**
> ```powershell
> Get-Item C:\rm26build | Select-Object Target
> # Target 必须是 ...\luojiafox\luojiamaster\源码
> ```
> 指错了就重建：

## 4. 相对 ACE 原版的全部改动

**完整逐行 diff 见 `改动清单.diff.md`。** 以下为改动摘要与原因。

### 4.1 必须改（否则功能不完整）

#### ① `src/keyboard_mouse_state_manager.cpp` —— 键盘位掩码恒为 0

**问题**：原版 16 个按键全部使用 `ImGui::IsKeyPressed()`。该 API 仅在「按下的那一帧」返回 true。而此函数以 **75Hz（13ms）** 反复采样，按住按键时绝大多数采样点都落在「已按下但不是新按下」的状态，导致 `keyboard_value` **恒为 0**。

**实测证据**：改造前监控日志 `键: (无) | 鼠标: X=23 Y=19 Z=0`；改造后 `键: W | 鼠标: X=-6 Y=11 Z=0`。

**修复**：
```cpp
// 改前
keyboard_value[0] = ImGui::IsKeyPressed(ImGuiKey_W);
// 改后
keyboard_value[0] = ImGui::IsKeyDown(ImGuiKey_W);
```
16 个按键全部替换。**注意：`Esc` / `H` / `I` 三处必须保留 `IsKeyPressed`**，因为它们是「点按触发」语义。

#### ② `src/platform/windows_platform_backend.cpp` —— 鼠标到边缘失控

**问题**：原版 `SetGameInputCapture(true)` 只做了 `ClipCursor()` + `ShowCursor(FALSE)`，没有重置光标。鼠标顶到窗口/屏幕边缘后，`io.MouseDelta` 恒为 0，云台不再转动。

**修复**（两处配合）：

1. `BeginFrame()` 中，在 ImGui 采样之前，读取真实位移并回中：
```cpp
if (game_input_captured_) {
    POINT cursor{};
    if (::GetCursorPos(&cursor)) {
        POINT center{};
        RECT rect;
        ::GetClientRect(hwnd_, &rect);
        center.x = (rect.right - rect.left) / 2;
        center.y = (rect.bottom - rect.top) / 2;
        ::ClientToScreen(hwnd_, &center);
        add_raw_mouse_delta((float)(cursor.x - center.x), (float)(cursor.y - center.y));
        ::SetCursorPos(center.x, center.y);   // 回中
    }
}
```
2. `SetGameInputCapture()` 中同步切换位移来源：
```cpp
enabled ? set_use_raw_mouse(true) : set_use_raw_mouse(false);
```

**注意顺序**：必须在 `ImGui_ImplDX12_NewFrame()` **之前**读取并回中，否则当帧位移被抵消。

#### ③ `src/keyboard_mouse_state_manager.h/.cpp` —— 原始位移接口

新增两个全局函数供平台层调用：

```cpp
void add_raw_mouse_delta(float dx, float dy);  // 平台层每帧累积
void set_use_raw_mouse(bool enabled);          // 是否使用原始位移
```

`update_keyboard_mouse_state()` 中：
```cpp
if (use_raw_mouse) {
    mouse_x += (int32_t)(raw_mouse_dx * mouse_sensitivity);
    mouse_y += (int32_t)(raw_mouse_dy * mouse_sensitivity);
    raw_mouse_dx = raw_mouse_dy = 0.0f;
} else {
    mouse_x += (int32_t)(io.MouseDelta.x * mouse_sensitivity);
    mouse_y += (int32_t)(io.MouseDelta.y * mouse_sensitivity);
}
```

#### ④ 180° 旋转迁移到 GPU

**问题**：原版在 `AvFrameRgbaConverter` 中对每帧做 `ApplyRgba180Rotation()` —— 1080p × 4 通道 = **207 万像素逐字节交换**，纯 CPU，且与渲染/键鼠采样同线程。

**修复**：
- `src/app/application.cpp`：删除该调用
- `src/main_window.cpp`：主画面改用 UV 翻转
  ```cpp
  const ImVec2 uv0 = inverted ? ImVec2(1,1) : ImVec2(0,0);
  const ImVec2 uv1 = inverted ? ImVec2(0,0) : ImVec2(1,1);
  draw_list->AddImage(tex, min, max, uv0, uv1);
  ```
- `src/panel/custom_video_panel.cpp`：副画面同理（`ImGui::Image(tex, size, uv0, uv1)`）

> `video/rgba_image_transform.cpp` 保留但已不再被调用，可删除。

## 5. 协议实现要点（开发参考）

> 依据《RoboMaster 2026 机甲大师高校系列赛通信协议 V2.0.0》。

### 5.1 MQTT

- 协议版本：MQTT 3.1.1
- 连接参数：`clean_session=true`、`keep_alive=5s`、**空用户名密码**
- **clientID = 机器人 ID**（红方英雄=1、工程=2、步兵=3/4/5、空中=6、哨兵=7；蓝方 +100）
- 服务器：`192.168.12.1:3333`（官方协议定义），实际取决于选手端监听地址

### 5.2 订阅的 25 个 topic

```
GameStatus              GlobalUnitStatus        GlobalLogisticsStatus
GlobalSpecialMechanism  Event                   RobotInjuryStat
RobotRespawnStatus      RobotStaticStatus       RobotDynamicStatus
RobotModuleStatus       RobotPosition           Buff
PenaltyInfo             RobotPathPlanInfo       RadarInfoToClient
MapClickInfo            CustomByteBlock         TechCoreMotionStateSync
RobotPerformanceSelectionSync  DeployModeStatusSync
RuneStatusSync          SentryStatusSync        DartSelectTargetStatusSync
SentryCtrlResult        AirSupportStatusSync
```
全部 QoS 0。

### 5.3 发布的 topic

| topic | 频率 | 说明 |
|---|---|---|
| `KeyboardMouseControl` | 75Hz | `mouse_x/y/z`(int32 增量) + 左右中键(bool) + `keyboard_value`(uint32 位掩码) + 中键 |
| `CustomControl` | ~50Hz | 最大 30 字节自定义数据 |
| `MapClickCmd` | 触发式 | 地图标记 |

**键盘位掩码定义**（bit0~bit15）：
`W S A D Shift Ctrl Q E R F G Z X C V B`

### 5.4 UDP 图传

- 监听端口：**3334**
- 编码：HEVC（H.265）Elementary Stream
- 分辨率/fps：1920×1080 @60fps
- 每包 ≤1400 字节，**前 8 字节分片头（大端）**：
  ```
  [0:2]  frame_id       u16
  [2:4]  shard_index    u16
  [4:8]  frame_bytes    u32
  ```
- 负载上限 1392 字节
- 无重传机制

### 5.5 解码

`src/video/video_decoder.cpp` 当前优先尝试 `hevc_cuvid`，失败回退 `hevc` 软解。

**已知优化点**：未配置 AVHWAccel 参数，实际走软解。ffmpeg 库已包含 `d3d11va` / `dxva2` / `hevc_cuvid`，启用硬件解码可显著降低 CPU 占用。

## 6. 已知问题与后续优化

| 优先级 | 问题 | 说明 |
|---|---|---|
| P0 | **控制响应延迟** | 链路为 `luojiamaster → MQTT → 选手端 → COM5(VT13) → 无线 → 车`，比官方客户端多一跳 MQTT 转发 |
| P0 | **视频软解占 CPU** | 1080p60 HEVC 纯 CPU 解码 + `sws_scale` YUV→RGBA；建议启用 hwaccel |
| P1 | 图传分辨率 | 可评估降分辨率/帧率对延迟与 CPU 的收益 |
| P1 | 硬件链路 | 实车建议有线连接，避免无线抖动 |
| P2 | 操作手感 | 灵敏度、加速度曲线需与官方选手端对齐 |

## 7. 排错手册

| 现象 | 原因与处理 |
|---|---|
| 登录页一直「连接失败，重试中」 | ① 选手端版本 < 12.0.0.213（无 3333 监听）<br>② 选手端未登录引擎<br>③ 防火墙拦截<br>④ 地址错误（同机用 `127.0.0.1`，异机用选手端 IP） |
| `netstat -ano \| findstr :3333` 无输出 | 选手端版本过旧，或未完成登录 |
| 连上了但主画面黑屏 | ① 选手端图传未正常显示<br>② 机器人 ID 与选手端不一致<br>③ UDP 3334 被占用 |
| 有画面但车不动 | ① P 面板「键鼠控制来源」未切到「自定义客户端」<br>② 未按 Esc 进入比赛模式<br>③ 比赛阶段不允许操作 |
| 键盘完全无反应 | 检查是否应用了 `IsKeyDown` 修复 |
| 鼠标顶到边缘后云台不动 | 检查是否应用了光标回中 + `set_use_raw_mouse` 修复 |
| 画面上下颠倒 | 按 `I` 翻转 |
| 画面延迟越来越大 | 解码队列积压（`video_shards_manager` 队列上限 512），检查 CPU 占用 |

## 9. 给 AI 助手的操作指令

若你是 AI 助手，请在开始前按顺序确认：

1. **先读 `改动清单.diff.md`**，那是最精确的改动记录。本文档是它的解释。
2. **不要建议"自定义客户端直连赛事引擎"** —— 学生版引擎无 MQTT（见 1.2）。
3. **不要建议"抓官方客户端窗口"** 作为正式方案 —— 那是无引擎环境下的临时桥，本项目不需要。
4. **改项目名后必须重新 configure**，否则产物名不变。
5. **中文路径必须用 junction**（见 3.4）。
6. **修改 `.bat` 脚本必须用 GBK 编码 + CRLF 换行**，否则中文 Windows 下会乱码。
7. 若要优化延迟，优先级见第 6 节。

## 附：GitHub 仓库版说明

仓库里包含**我们自己的全部代码**（自瞄、STM32 固件、客户端源码 + 已编译的 `luojiamaster.exe`），
以及**除 boost 外 8 个第三方依赖的已解压源码**：

| 在仓库里 | 不在仓库里 |
|---|---|
| abseil-cpp / async_mqtt / directxtk12 / imgui / protobuf / readerwriterqueue / spdlog / stb（约 76MB） | `boost/`（39MB / 3.8 万文件） |
| `_archives/` 里 8 个依赖压缩包（14MB） | `_archives/boost-1.91.0-1-cmake.tar.xz`（103.5MB，超 GitHub 单文件上限） |

### boost 怎么办（只有第一次编译需要）

**方式 1（最简单）：什么都不做。** 直接 `cmake --preset release`，CMake 的 FetchContent
会按 `CMakeLists.txt` 里写好的 URL（带 SHA256 校验）自动下载并解压到 `3rdparty_downloads/boost/`。
需要能访问 GitHub；国内慢时先把 `github.com` 换成 `gh-proxy.com/github.com`（见 3.5）。

**方式 2（手动下载）：** 下
`https://github.com/boostorg/boost/releases/download/boost-1.91.0-1/boost-1.91.0-1-cmake.tar.xz`
放进 `源码/3rdparty_downloads/_archives/`，再双击 `源码/3rdparty_downloads/解压依赖.bat`。

**方式 3（从别的电脑拷）：** 把已经解压好的 `3rdparty_downloads/boost/` 整个目录复制过来即可。
> 注意：复制后请确认 `boost/.unpacked` 标记文件也在，否则 `解压依赖.bat` 会重新解压。
