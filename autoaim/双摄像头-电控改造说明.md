# 双摄像头 —— 电控需要做的事

> 目标：让**自瞄上位机的工业相机画面**显示到**自定义客户端**的第二视角（H 键切换）
>
> 参与方：视觉（上位机/自瞄）、电控（主控固件）、软件（自定义客户端）
> 日期：2026-10-18

---

## 一、整体链路

```
大恒工业相机
    ↓ USB
Jetson 自瞄程序（视觉负责改造）
    ↓ USB CDC 串口（现有链路，新增视频帧）
STM32 主控（电控负责改造）
    ↓ 串口（需要新增，见第三节）
VT03 图传发送端
    ↓ 无线
VT13 接收端 → 官方选手端 → 自定义客户端（已支持，无需改动）
```

**关键点：客户端已经做好了，不需要改。** 客户端按 H 键就能切换到 `CustomByteBlock` 视频流。

---

## 二、协议规定（来自官方通信协议）

图传链路的自定义数据通道：

| 项 | 数值 |
|---|---|
| 命令码 | `0x0310` |
| 数据段长度 | **固定 300 字节** |
| 所属链路 | 图传链路（主控 ↔ 图传发送端） |
| 发送方 | 自定义客户端 → 图传链路 → 机器人（本场景为机器人内部转发） |

**注意方向**：协议里 `0x0310` 写的是"机器人发送给自定义客户端"，即机器人 → 客户端方向的**自定义数据流**。
视频数据正是走这个方向。机器人主控收到上位机的视频包后，按 `0x0310` 格式发给图传发送端。

### 0x0310 帧格式

```
+--------+--------+--------+--------+--------+---------+--------+--------+----------+
|  0xA5  | len_lo | len_hi |  seq   |  CRC8  | cmd_lo  | cmd_hi |  data  |  CRC16   |
+--------+--------+--------+--------+--------+---------+--------+--------+----------+
   1B       1B       1B       1B       1B       1B        1B      300B      2B
   ^                      ^                                      ^
   帧头                 CRC8（前4字节）                        CRC16（前 7+300 字节）
```

| 字段 | 偏移 | 长度 | 说明 |
|---|---|---|---|
| SOF | 0 | 1 | 固定 `0xA5` |
| data_length | 1 | 2 | **固定 `300`**（小端） |
| seq | 3 | 1 | 包序号，自增（0~255 循环） |
| CRC8 | 4 | 1 | 前 4 字节的 CRC8（多项式 `0x8C`，初值 `0xFF`） |
| cmd_id | 5 | 2 | **固定 `0x0310`**（小端，即 `0x10 0x03`） |
| data | 7 | 300 | 视频压缩数据（不足补 0） |
| CRC16 | 307 | 2 | 前 307 字节的 CRC16（多项式 `0x1189`，初值 `0xFFFF`） |

**整帧总长：309 字节**

## 三、电控需要改的三处

### 1. USB CDC 接收：区分"控制帧"和"视频帧"

**现状**（`gimbal_project/Src/usbd_cdc_if.c`）：

```c
static int8_t CDC_Receive_FS(uint8_t* Buf, uint32_t *Len)
{
  memcpy(Usart_Receive, Buf, 40);      // ← 固定拷 40 字节
  usbd_cdc_receive_handle();
  ...
}
```

**问题**：
- 固定 40 字节，无法容纳视频流
- 视频数据量大（300 字节/包 × 40Hz = 12KB/s），会和控制帧混在一起

**建议改法**：在应用层增加一个"流式解析器"，按帧头区分两种帧：

```c
// 建议在 Self_aim.c 的 process_usb_data_packet 里扩展

// 1. 控制帧：0xFF 开头，32 字节（现有三阶指令）
// 2. 视频帧：0xA5 开头，309 字节（0x0310）

// 伪代码
void process_usb_data(uint8_t *data, uint16_t len)
{
    for (每个字节 b) {
        if (state == WAIT_HEAD) {
            if (b == 0xFF) state = CONTROL_FRAME;
            else if (b == 0xA5) state = VIDEO_FRAME;
        }
        else if (state == CONTROL_FRAME) { 累积到 32 字节 → 解析三阶指令 }
        else if (state == VIDEO_FRAME)   { 累积到 309 字节 → 转发到 VT03 串口 }
    }
}
```

**注意**：`CDC_Receive_FS` 的 `memcpy(..., 40)` 要改成使用实际的 `*Len`。

### 2. 新增：把视频帧转发到 VT03 串口

**现状**：主控代码里**完全没有 0x0310 相关代码**（已全仓库搜索确认）。

**需要新增**：

```c
// 收到完整的 309 字节 0x0310 帧后
void forward_video_to_vt03(uint8_t *frame, uint16_t len)
{
    // 直接原样透传即可（如果主控和 VT03 之间就是标准 0x0310）
    HAL_UART_Transmit(&huartX, frame, len, 10);
}
```

**关键是确定 `huartX` 是哪个串口。**

### 3. 确认 VT03 接在哪个串口（**最关键，需要硬件核实**）

**当前串口占用**（`gimbal_project/Src/usart.c`）：

| 串口 | 波特率 | 当前用途 | 引脚 |
|---|---|---|---|
| USART1 | 9600 | 裁判系统 | PB7(RX) / PA9(TX) |
| USART3 | 100000 | 遥控器 DBUS | PC11(RX) / PC10(TX) |
| **USART6** | **921600** | **代码里被遥控 SBUS 占用** ⚠️ | PG14(TX) / PG9(RX) |

**问题**：

`remote_control.c` 里 `USART6_IRQHandler` 正在解析遥控信号，但 `921600` 恰好是 VT03 图传发送端的标准波特率。

**三种可能，必须核实**：

**A. VT03 确实接在 USART6，但遥控已经不用 SBUS 了**
→ 需要删掉 `remote_control.c` 里的 USART6 中断和 DMA 配置，腾出来给视频

**B. VT03 接在别的串口（可能没初始化）**
→ 需要新增串口初始化和引脚配置

**C. VT03 由另一块板子（裁判系统主控模块）转发**
→ 那么 0x0310 要走裁判系统那条链路，和现在讨论的主控直连不同

**请核实：VT03 图传发送端的 UART 线，物理上接在 STM32 的哪个引脚？**

## 附：CRC 算法（如需自行校验）

```c
// CRC8：多项式 0x8C，初值 0xFF
uint8_t get_crc8(const uint8_t *data, size_t len) {
    uint8_t crc = 0xFF;
    while (len--) crc = CRC8_TAB[crc ^ (*data++)];
    return crc;
}

// CRC16：多项式 0x1189，初值 0xFFFF
uint16_t get_crc16(const uint8_t *data, size_t len) {
    uint16_t crc = 0xFFFF;
    while (len--) crc = (crc >> 8) ^ CRC16_TAB[(crc ^ (*data++)) & 0xFF];
    return crc;
}
```
