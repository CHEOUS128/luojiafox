# 双摄像头图传 —— 电控改造说明（可直接照做）

> 目标：让自瞄工业相机画面显示到自定义客户端（H 键切换的第二视角）。
> 参与方：视觉（已完成）、电控（本文档）、软件（客户端已支持，无需改）
> 版本：v3 定版（2026-10-20）
> 对应视觉版本：`autoaim/my_lf_INF_20261025`

---

## 〇、你要做的三件事（先看这里）

1. **改 USB 接收**：`CDC_Receive_FS` 不再写死 40 字节，改成按帧头分流（0xFF 控制帧 / 0xA5 视频帧）
2. **加一个转发函数**：收到完整 309 字节视频帧，**原样**写给 VT03 串口
3. **确认 VT03 接在哪个 UART**，把 `huart_vt03` 指对（见第四节）

预计改动量：新增 1 个 `.c/.h`（约 150 行），修改 `usbd_cdc_if.c` 1 处、`Self_aim.c` 1 处。

**串口带宽**：最高 40 包/秒 × 309 字节 ≈ 12.4 KB/s，921600 波特率（≈92 KB/s）足够。

---

## 一、链路与分工

```
大恒相机 → Jetson 自瞄程序（已完成）
    ↓ USB CDC（/dev/ttyACM0，虚拟串口）
STM32 主控                    ← 本文档要改的地方
    ↓ UART（921600，VT03 标准波特率）
VT03 图传发送端
    ↓ 无线 → 裁判系统
                                                                  ↓
                                             自定义客户端（H 键切换，已支持）
```

视觉端已经验证：0x0310 帧的帧头、长度、CRC8、CRC16、序号全部正确。
电控只需要**不破坏、不重排**地把 309 字节送出去。

## 二、协议：0x0310 帧（固定 309 字节）

### 2.1 外层（对外，电控要按这个找帧头）

```
偏移      长度    内容
[0]       1      0xA5                 帧头
[1:3]     2      0x2C 0x01            数据段长度 = 300（小端）
[3]       1      seq                  外层序号 0~255 循环
[4]       1      CRC8                 前 4 字节，多项式 0x8C，初值 0xFF
[5:7]     2      0x10 0x03            cmd_id = 0x0310（小端）
[7:307]   300    data                 视频数据（内部还有一层，见 2.2）
[307:309] 2      CRC16                前 307 字节，多项式 0x1189，初值 0xFFFF（小端）
```

### 2.2 data 段内部（客户端解包规则，电控**不需要理解**，更不能修改）

```
[2B 内层包长度 大端][2B 内层序号 大端][H.264 片段 ≤296B] + 补 0
```

> ⚠️ **只做透传**：不要改字节、不要重算 CRC、不要改长度、不要拆包重排。
> data 里可能出现 0xFF、0xA5 等任意字节，**必须按长度计数走完 309 字节**，
> 不能在中间重新找帧头，否则会错位。

### 2.3 与控制帧的区别

| 帧类型 | 帧头 | 长度 | 方向 |
|---|---|---|---|
| 云台控制帧（现有） | `0xFF` | 32 字节 | 上位机 → 主控 |
| 视频帧（新增） | `0xA5` | 309 字节 | 上位机 → 主控 → VT03 |

static uint8_t calc_crc8(const uint8_t *d, uint16_t n)
{
  uint8_t c = 0xFF;
  while (n--) c = crc8_tab[c ^ (*d++)];
  return c;
}
static uint16_t calc_crc16(const uint8_t *d, uint32_t n)
{
  uint16_t c = 0xFFFF;
  while (n--) c = (c >> 8) ^ crc16_tab[(c ^ (*d++)) & 0xFF];
  return c;
}

/* ================= 状态机 ================= */
typedef enum { ST_WAIT_HEAD = 0, ST_COLLECT = 1 } vf_state_t;

static vf_state_t s_state = ST_WAIT_HEAD;
static uint16_t   s_idx   = 0;
static uint8_t    s_buf[VIDEO_FRAME_BYTES];

/* 队列（单生产者：USB 回调；单消费者：主循环） */
static uint8_t  s_queue[VIDEO_QUEUE_DEPTH][VIDEO_FRAME_BYTES];
static volatile uint8_t s_q_head = 0;   /* 写 */
static volatile uint8_t s_q_tail = 0;   /* 读 */

static volatile uint32_t s_forwarded = 0;
static volatile uint32_t s_crc_err   = 0;
static volatile uint32_t s_overflow  = 0;

void VideoForward_Init(void)
{
  s_state = ST_WAIT_HEAD;
  s_idx = 0;
  s_q_head = s_q_tail = 0;
  s_forwarded = s_crc_err = s_overflow = 0;
}

/* 校验整帧；通过返回 1 */
static int video_frame_is_valid(const uint8_t *f)
{
  /* 帧头 */
  if (f[0] != VIDEO_SOF) return 0;
  /* 长度字段（小端）= 300 */
  if (f[1] != (uint8_t)(VIDEO_DATA_BYTES & 0xFF)) return 0;
  if (f[2] != (uint8_t)((VIDEO_DATA_BYTES >> 8) & 0xFF)) return 0;
  /* cmd_id（小端）= 0x0310 */
  if (f[5] != 0x10 || f[6] != 0x03) return 0;
  /* CRC8 覆盖前 4 字节 */
  if (f[4] != calc_crc8(f, 4)) return 0;
  /* CRC16 覆盖前 307 字节（小端存放） */
  {
    uint16_t recv = (uint16_t)(f[307] | (f[308] << 8));
    if (recv != calc_crc16(f, VIDEO_HEAD_BYTES + VIDEO_DATA_BYTES)) return 0;
  }
  return 1;
}

void VideoForward_Feed(const uint8_t *data, uint16_t len)
{
  uint16_t i;
  if (data == NULL) return;

  for (i = 0; i < len; i++) {
    uint8_t b = data[i];

    if (s_state == ST_WAIT_HEAD) {
      if (b == VIDEO_SOF) {
        s_buf[0] = b;
        s_idx = 1;
        s_state = ST_COLLECT;
      }
      /* 其它字节：丢弃（0xFF 控制帧由原状态机处理，见 3.4） */
      continue;
    }

    /* ST_COLLECT：按字节数收满 309，中途不找帧头 */
    s_buf[s_idx++] = b;
    if (s_idx >= VIDEO_FRAME_BYTES) {
      s_state = ST_WAIT_HEAD;
      s_idx = 0;

      if (!video_frame_is_valid(s_buf)) {
        s_crc_err++;
        continue;
      }

      /* 入队 */
      {
        uint8_t next = (uint8_t)((s_q_head + 1u) % VIDEO_QUEUE_DEPTH);
        if (next == s_q_tail) {
          /* 队列满：丢最老的一帧，保证延迟不累积 */
          s_q_tail = (uint8_t)((s_q_tail + 1u) % VIDEO_QUEUE_DEPTH);
          s_overflow++;
        }
        memcpy(s_queue[s_q_head], s_buf, VIDEO_FRAME_BYTES);
        s_q_head = next;
      }
    }
  }
}

void VideoForward_Task(void)
{
  while (s_q_tail != s_q_head) {
    const uint8_t *frame = s_queue[s_q_tail];

    if (HAL_UART_Transmit(HUART_VT03, (uint8_t *)frame, VIDEO_FRAME_BYTES,
                          VIDEO_UART_TIMEOUT_MS) == HAL_OK) {
      s_forwarded++;
    }

    s_q_tail = (uint8_t)((s_q_tail + 1u) % VIDEO_QUEUE_DEPTH);
  }
}

uint32_t VideoForward_GetForwarded(void) { return s_forwarded; }
uint32_t VideoForward_GetCrcError(void)  { return s_crc_err; }
uint32_t VideoForward_GetOverflow(void)  { return s_overflow; }

### 3.3 修改 `Src/usbd_cdc_if.c`

找到 `CDC_Receive_FS`，把写死的 40 字节改成按实际长度喂给流式解析器：

```c
static int8_t CDC_Receive_FS(uint8_t* Buf, uint32_t *Len)
{
  /* USER CODE BEGIN 6 */
  /* 原来的：memcpy(Usart_Receive,Buf,40); usbd_cdc_receive_handle(); */
  usbd_cdc_receive_handle((uint8_t *)Buf, (uint16_t)(*Len));   /* 改成带长度 */

  USBD_CDC_SetRxBuffer(&hUsbDeviceFS, Buf);
  USBD_CDC_ReceivePacket(&hUsbDeviceFS);
  return (USBD_OK);
  /* USER CODE END 6 */
}
```

### 3.4 修改 `application/Self_aim.c` / `Self_aim.h`

现有 `process_usb_data_packet()` 只识别 `0xFF` 控制帧，而且**每轮结束会 `return`**，
会把同一批数据里后面的视频帧吞掉。改为"先分流、再分别解析"：

```c
/* Self_aim.h 新增 */
void usbd_cdc_receive_handle(uint8_t *data, uint16_t len);
```

```c
/* Self_aim.c 新增 #include "video_forward.h" */

/* 只处理控制帧（原逻辑，帧头 0xFF，32 字节）。把 return 改成 break/continue 语义 */
static void process_control_bytes(const uint8_t *data, uint16_t length)
{
    static uint8_t  ctrl_buf[sizeof(RECEIVE_DATA)];
    static uint16_t ctrl_idx = 0;

    for (uint16_t i = 0; i < length; i++) {
        uint8_t b = data[i];
        if (ctrl_idx == 0) {
            if (b == FRAME_HEADER_FF) ctrl_buf[ctrl_idx++] = b;
        } else if (ctrl_idx < sizeof(RECEIVE_DATA)) {
            ctrl_buf[ctrl_idx++] = b;
            if (ctrl_idx == sizeof(RECEIVE_DATA)) {
                memcpy(&inputdata, ctrl_buf + sizeof(FrameHeader), sizeof(InputData));
                ctrl_idx = 0;
            }
        } else {
            ctrl_idx = 0;
        }
    }
}

/* 统一入口：先分离出视频帧，剩下的交给控制帧解析 */
void usbd_cdc_receive_handle(uint8_t *data, uint16_t len)
{
    /* 视频解析器内部只吃 0xA5 开头的 309 字节帧，
       其它字节直接忽略；控制帧解析器只吃 0xFF 开头的 32 字节帧。
       两个解析器都各自维护状态，互不影响。 */
    VideoForward_Feed(data, len);
    process_control_bytes(data, len);
}
```

> 说明：两个解析器各扫一遍同一段数据，简单可靠。
> 视频解析器在 `ST_COLLECT` 期间会把控制帧字节也吞进它的 309 字节里——
> 但视觉端发送频率低（≤40 包/秒），控制帧 1000Hz，实际几乎不会交错；
> 即使交错，视频帧 CRC 校验失败会被丢弃，控制帧解析器独立计数，互不污染。

## 四、确认 VT03 接在哪个 UART（**必须先回答**）

### 4.1 当前工程串口占用（已核对源码）

| UART | 波特率 | 引脚 | 当前用途 |
|---|---|---|---|
| USART1 | 9600 | PB7(RX) / PA9(TX) | 裁判系统 |
| USART3 | 100000 | PC11(RX) / PC10(TX) | 遥控 DBUS（偶校验） |
| **USART6** | **921600** | PG14(TX) / PG9(RX) | **SBUS 遥控（DMA + 中断 `USART6_IRQHandler`）** |

`usart.c` 里 `MX_USART6_UART_Init()` 的波特率正好是 **921600**，和 VT03 标准波特率一致。

| 情况 | 判断依据 | 需要做什么 |
|---|---|---|
| **A. VT03 接 USART6** | 图传模块的 TX/RX 线接在 PG14/PG9 | 遥控已不用 SBUS → 注释掉 `remote_control.c` 里的 `USART6_IRQHandler` 和 `hdma_usart6_rx` 配置，把 USART6 让给 VT03；`HUART_VT03` 填 `&huart6` |
| **B. VT03 接其它 UART** | 线接在别的引脚 | 新增该 UART 初始化（921600），`HUART_VT03` 改成对应句柄 |
| **C. 还没接** | 没有图传模块 | 先接线，再按 A 或 B 处理 |

> ⚠️ **如果遥控还在用 SBUS（USART6），不要直接拿来发视频**，否则遥控会断。
> 这种情况必须新开一个 UART 给 VT03。

### 4.3 用逻辑分析仪/示波器快速判断（不需要看代码）

把探头放在 PG14/PG9：
- 空闲时高电平、有 921600 的密集数据 → 是图传或 SBUS，看数据长度区分（SBUS 每帧 25 字节、帧头 0xA9 0x53）
- 插上 VT03 断电/上电，看这条线有没有变化

## 六、验收标准

| 项目 | 标准 |
|---|---|
| 串口抓包 | 每帧 309 字节，帧头 0xA5，长度字段 0x2C 0x01 |
| 转发一致性 | VT03 端收到的字节与 USB 端**逐字节一致** |
| CRC | 视觉端发送的帧 100% 通过；电控侧 `crcError` 应为 0 |
| 云台控制 | 打开视频后，自瞄 FPS 仍保持 70+，云台不抖 |
| 客户端 | H 键切换后能看到画面，帧率 ≥ 8fps，无持续花屏 |

## 七、常见问题排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 客户端完全没画面 | VT03 串口没接对 / 没转发 | 用逻辑分析仪确认 VT03 线上有 309 字节帧 |
| 画面偶尔花屏 | 队列溢出或串口丢字节 | 看 `overflow` 计数；降低 `VIDEO_QUEUE_DEPTH` 或提高主循环调用频率 |
| 画面一直花屏 | 封装被改写 | 确认**原样透传**，没有重算 CRC、没有改长度 |
| 云台控制变乱 | `video_send_enable` 打开了但电控还没分流 | 先关掉视觉端视频，完成 3.3/3.4 再打开 |
| 遥控失效 | USART6 被 VT03 占用 | 见 4.2，SBUS 仍在用就必须换 UART |
| 帧率很低 | 主循环里 `HAL_UART_Transmit` 阻塞 | 确认 `VideoForward_Task()` 在主循环调用，不在 USB 回调里 |
