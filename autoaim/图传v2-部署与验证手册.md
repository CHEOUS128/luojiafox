## 三、离线 + 真实相机测试（不接主控）

```bash
cd ~/my_lf_INF_20261025

# 1) 真实相机 + 画质对比图（必须 sudo，logs/ 是 root 的）
sudo ./build/video_sender_test /tmp -c configs/standard3.yaml --compare

# 2) 帧格式校验（不需要 sudo）
python3 tests/verify_frames.py /tmp/video_test_frames.bin tools/crc.cpp
```

**预期**：

```
=== 外层校验（0x0310 帧）===
帧头 0xA5:     xxx/xxx      ← 全过
长度 300:      xxx/xxx
cmd 0x0310:    xxx/xxx
CRC8:          xxx/xxx
CRC16:         xxx/xxx

=== 内层校验（transport packet）===
含有效内层包:  xxx/xxx
载荷非空:      xxx/xxx
H.264 总字节:  ...
短包(<296B):   ~1/帧 (约 15~20%)   ← 正常
内层 seq 连续: ✅
✅ 全部检查通过
```

**短包占比异常**：

- 约 1 个/帧（10~30%）：正常，每帧最后一个 NAL 不满 296 字节
- 几乎 100% 都是短包：文件没覆盖成功，还在跑旧版
- 0%：不太可能，可能是关键帧特别大

**画质对比**（把这三个文件拉回 Windows 看）：

```bash
# 生成编码后的一帧
ffmpeg -y -v error -i /tmp/video_test_stream.h264 -frames:v 1 -update 1 /tmp/video_test_encoded.png
ls -la /tmp/video_test_last.png /tmp/video_test_view.png /tmp/video_test_encoded.png
```

| 文件 | 看什么 |
|---|---|
| `video_test_last.png` | 相机原始 1280×1024 |
| `video_test_view.png` | 取景+锐化后的 300×240（看视野对不对） |
| `video_test_encoded.png` | 解码回来的 300×240（看糊的程度） |

**判断标准**：

- `view` 里应能看到**整幅画面**（上下黑边），而不是只有中间一块
- `encoded` 比 `view` 糊是正常的（码率限制），但应能辨认场景轮廓/装甲板颜色
- 还是太糊就再调：`--kbps 95 --preset slow --sharpen 0.8` 再跑一次对比

**取景方案（已定：全视野，不裁任何像素）**：

| 方案 | 配置 | 特点 |
|---|---|---|
| 全视野（当前采用） | `video_keep_aspect: true`，300×240 | 整幅 1280×1024 等比缩小，视野完整、无黑边；客户端等比完整显示 |
| 贴 ACE（备选） | `video_keep_aspect: false` + `video_crop_size: 1000` | 中心裁 1000×1000 再缩，物体大 28%，但左右各丢约 11% 视野 |
| 旧方案（弃用） | `video_keep_aspect: false` + `video_crop_size: 300` | 只留中间 23% 宽，视野丢失严重 |

> 客户端显示规则：自定义流（H 键切换后）永远等比完整显示、居中，不裁剪、不拉伸；
> 只有官方图传作主画面时才会拉伸铺满。所以**发送端裁掉的部分，操作手永远看不到**。

**看动态效果**：

## 四、给电控的假帧脚本（可选）：验证主控转发

如果电控要单独验证"收到 309 字节 → 原样转发"，用这个脚本造一条合法假帧：

```bash
cd ~/my_lf_INF_20261025
python3 tools/make_fake_frame.py /tmp/fake_0310.bin --count 200
python3 tests/verify_frames.py /tmp/fake_0310.bin tools/crc.cpp   # 应全部通过

# 直接往串口灌（注意：自瞄程序必须停掉，否则两个进程抢串口）
sudo systemctl stop autoaim
sudo stty -F /dev/ttyACM0 raw
sudo cat /tmp/fake_0310.bin > /dev/ttyACM0
```

电控在 VT03 串口用串口助手/逻辑分析仪抓，应看到**逐字节一致**的 309 字节帧。

## 七、已知限制

1. `video_send_enable` 默认 `false`：电控改完之前**不要打开**，否则 309 字节帧会被主控当控制帧，云台会乱。
2. 发送节拍 40Hz：由 `VideoSender::drain_due` 控制，`tools::get_crc8` 等不变。
3. 如果主循环 FPS 掉到 40 以下，视频包会积压并被丢弃（日志每 5 秒提示一次）。
4. 带宽上限是物理的：40Hz × 296B ≈ 94.7kbps，清晰度不可能超过这个天花板。
