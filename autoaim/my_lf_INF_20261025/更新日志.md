## 一、本版目标与边界

**目标**：把自瞄工业相机画面送到自定义客户端第二视角（客户端按 H 键切换），先跑通链路。

**本版已完成**：取图 → 全视野缩放 → H.264 编码 → 按客户端格式封装 0x0310 → 串口输出 → 自测校验全过。

**本版未做**（留待链路跑通后优化）：
- 帧率精调（实测约 8~10fps，编码在独立线程，不影响自瞄主循环）
- 画质进一步调参（码率/preset/锐化已有基础配置，未做主观调优）
- 电控侧改造（需电控按 `双摄像头-电控改造说明.md` 完成）
- 服务切换到新版本（仍在跑 20261013）

> **重要**：`video_send_enable` 默认 `false`。电控改完之前**不要打开**，否则 309 字节视频帧会被主控当控制帧解析，云台会乱。

## 五、关键技术点

### 1. 客户端解包格式（按客户端源码实现）

客户端 `CustomByteBlockVideoDecoder` 期望 0x0310 的 300 字节 data 是**双层结构**：

```
data (300B) =
  [2B 内层包长度 BE][2B 序号 BE][H.264 片段]
  （每个 0x0310 帧只装 1 个内层包；剩余补 0；长度为 0 表示填充结束）

内层包长度 = 2 + 载荷长度，最大 298；载荷最大 296 字节
```

若直接塞裸 H.264，客户端读到起始码 `00 00` 会当成"长度 0"整包丢弃——这是原实现客户端解不出来的原因。

### 2. 每帧尾巴立即发出

编码器输出常以整帧/NAL 为单位，每帧末尾通常不足 296 字节。原实现攒满 296 才发，
尾巴会滞留到下一帧甚至永久滞留；客户端每个包独立解析，接续的数据会丢失。
现在每帧剩余字节**立即封包发出**（补 0 到 300）。

### 3. 编码在独立线程

`preset=slow` 在 Jetson 上单帧编码约 66ms。若在自瞄主循环里同步编码，
主循环（约 10ms/轮）会被周期性卡住，云台控制会抖。

`VideoSender` 内部起工作线程：

- `feed()` 只做三件事：按 fps 节流、把最新帧交给线程（浅拷贝）、非阻塞取走到点的包
- 取景/锐化/编码/封包全在工作线程
- 只保留最新一帧：编码慢于 fps 时自动丢旧帧，延迟不累积
- 析构时 join；`flush()` 会等工作线程当前编码完成（最多 300ms）

### 4. 发送节拍：40Hz 令牌桶

与 ACE 编码端 `center_crop_packet_send_rate_hz: 40` 一致。
按真实流逝时间积令牌（上限 4 个突发），长期平均严格 40 包/秒。
待发包超过 20 个（0.5 秒量）时丢最老的，保证延迟不无限累加（日志每 5 秒提示一次）。

### 5. 全视野取景（本版决定）

1280×1024 整幅等比缩放到 **300×240**（两者都是 5:4，缩放后无黑边、不裁任何像素）。

客户端显示规则（源码核实）：自定义流（H 键切换后）永远等比完整显示、居中、不裁剪；
只有官方图传作主画面时才拉伸铺满。因此发送端裁掉的部分操作手永远看不到。

备选（未启用）：`video_keep_aspect: false` + `video_crop_size: 1000`，中心裁 1000×1000，
物体大 28%，但左右各丢约 11% 视野。

## 六、0x0310 帧格式（309 字节）

```
偏移    长度   内容
0       1     0xA5               帧头
1       2     0x2C 0x01          数据长度 300（小端）
3       1     seq                包序号（0~255 循环）
4       1     CRC8               前 4 字节，多项式 0x8C 初值 0xFF
5       2     0x10 0x03          cmd_id = 0x0310（小端）
7       300   data               双层封装（见第五节第 1 点），不足补 0
307     2     CRC16              前 307 字节，多项式 0x1189 初值 0xFFFF（小端）
```

## 七、配置项（`configs/standard3.yaml`）

```yaml
video_send_enable: false      # 联调通过后改为 true
video_width: 300              # 输出宽
video_height: 240             # 输出高：300x240 = 5:4，与相机 1280x1024 一致，全视野无黑边
video_keep_aspect: true       # true=整幅缩放（全视野）；false=中心裁剪
video_fps: 10.0               # 帧率
video_bitrate_kbps: 90        # 码率（通道上限约 94.7kbps）
video_crop_size: 300          # 仅 keep_aspect=false 时有效
video_x264_preset: "slow"     # 画质明显好于 veryfast
video_sharpen: 0.6            # USM 锐化强度（0=关闭）
```

## 十一、电控完成后如何做到"开机即完整功能"

**现状**：服务 `autoaim` 指向 20261013（无图传），配置文件里 `video_send_enable: false`。
所以电控改完代码、直接开机，跑的还是旧版、没有画面。

**要变成"开机即完整功能、可直接上场"，需要视觉侧执行两步**（电控改代码是前提）：

1. 配置开启：`video_send_enable: true`
2. 服务切换：`autoaim` → `autoaim-20261025`（指向本版本，开机自启）

已提供一键脚本（在 Jetson 上执行一次即可，之后永久生效）：

```bash
cd ~/my_lf_INF_20261025
sudo bash scripts/enable_video_service.sh
```

脚本会：备份配置 → 打开图传 → 创建并启用 `autoaim-20261025.service` →
停用旧的 `autoaim` → 启动 → 等待 20 秒打印状态与日志。

**回滚**（一条命令，回到 20261013 + 图传关闭）：

```bash
sudo bash scripts/rollback_to_20261013.sh
```

## 十二、回滚方式

```bash
# 关闭视频（最安全）
sed -i 's/^video_send_enable: true/video_send_enable: false/' configs/standard3.yaml

# 完全回退：服务仍指向 my_lf_INF_20261013，两个版本目录完全独立
sudo systemctl stop autoaim
sudo systemctl start autoaim
```
